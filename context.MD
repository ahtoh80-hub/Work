# Claude: лимиты токенов и уровень усилий

## 1. Когда обновляются токены (лимиты использования)

### Два разных понятия

| Что | Что это | «Обновление» |
|---|---|---|
| **Лимит использования** (сколько токенов можно потратить вообще) | Сколько Claude можно использовать за период | Обновляется **по времени** |
| **Окно контекста 1.0M** (память диалога) | Объём истории, который модель «видит» в сессии | **Не обновляется** — это «оперативная память», а не таймер |

### Подписка (Pro / Max)

- Действует **5-часовое окно**: отсчёт стартует с **первого запроса** в окне, а не по настенным часам.
  То есть лимит «откатывается» через 5 часов после первого сообщения — время сброса плавающее и сдвигается вместе с пользователем.
- На Max есть ещё **недельный лимит** — сбрасывается раз в 7 дней.
- Точное время до сброса: команда **`/usage`** в Claude Code (в веб-чате окно показывается в интерфейсе).
- Если достигнут лимит — сообщение само говорит, когда окно сбросится.

### API-ключ

- «окна» нет — работают rate limits (запросы/токены в минуту и в сутки) по тарифным уровням (tier), смотрятся в Console.

### Что делать, когда закончится 1.0M контекста

Это **не лимит использования** — ждать сброса не нужно, контекст нужно освободить:

1. **`/context`** — посмотреть, что сейчас занимает окно (файлы, CLAUDE.md, история).
2. **`/compact`** — сжать историю в саммари и **продолжить ту же сессию**.
3. **`/clear`** — начать свежую сессию (память проекта/CLAUDE.md сохраняется).
4. Профилактика:
   - не держать сессию «вечной» — очищать после завершённых задач;
   - держать CLAUDE.md компактным (~200 строк): он добавляется в каждый ход;
   - выгружать нужные файлы на диск и давать пути, а не тащить их в контекст целиком;
   - отключать расширенное thinking и лишние инструменты/MCP, когда не нужны;
   - для большой информации — проекты (RAG подтягивает только релевантное).

Если сработал **лимит использования** («reach your limit»): дождаться сброса 5-часового окна, переключить модель на `/model` на более лёгкую, либо приобрести кредиты/обновить план.

## 2. Уровень усилий (effort level)

### Где выбрать

**В веб-чате (claude.ai):**
1. Нажать на **название модели** рядом с кнопкой отправки.
2. Навести курсор на **«Усилия»** (Effort).
3. Выбрать уровень; там же переключатель **«Мышление»** (Thinking).

**В Claude Code:**
- **`/effort`** — выбор уровня прямо в сессии (уровни от `low` до `xhigh`/`max`, плюс `auto` — по умолчанию).
- **`claude --effort low`** — уровень при запуске сессии.
- Выбранный через `/effort` уровень **сохраняется и в следующих сессиях**.
- Уровень через `--effort`/`/effort` имеет приоритет над настройками; на Enterprise администратор может ограничить максимум.

### Какой уровень ставить

| Ситуация | Что делать |
|---|---|
| Не знаете, что ставить | Оставить **по умолчанию** — выверен под модель |
| Рутина: простые вопросы, базовые запросы, обычное письмо, мелкие правки | Снизить **на один уровень**, проверить качество. Не упало — снизить ещё |
| Сложное: математика, алгоритмы, планирование проекта, многоэтапные технические задачи | Поднять уровень и/или включить мышление |
| Критично по корректности, сложное кодирование (Opus 4.7+) | `xhigh`, для самого сложного — `max` (ответ дольше) |

### Важно про механизм

- Уровень усилий **не меняет знания модели** — он задаёт, сколько ресурсов модель тратит: сколько инструментов вызвать, сколько файлов прочитать, сколько шагов сделать до возврата к пользователю.
- Слишком низкий → модель рано останавливается с недоделанной работой, ходы тратятся на доводку (может выйти дороже).
- Слишком высокий → перерасход токенов, долгие ответы, «перемудрение».
- Менять **по одному уровню за раз** и смотреть на результат; сравнить расход — **`/usage`**.
- Ориентир: **сначала менять усилие, и только если не помогло — модель**. Если знаний достаточно, но «не старалась» — вопрос усилий, а не модели.
- Другой сигнал к смене модели: модель имела весь нужный контекст, честно старалась и всё равно ошиблась.

### Быстрая проверка влияния на токены (из документации Academy)

Три отдельные сессии в пустых папках:

```bash
claude --effort low    # run 1
claude                 # run 2, затем /effort auto
claude --effort max    # run 3
```

В каждой сессии выполнить одинаковый промпт, затем `/usage` — количество токенов должно расти от low к max.
