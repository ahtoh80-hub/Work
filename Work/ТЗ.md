## 1. Назначение и цель

- Настольное приложение (Windows, WPF, .NET 8) для импорта таблиц сигналов (IO List) систем АСУ ТП **произвольной структуры** из Excel (`.xlsx`) в базу Microsoft Access (`.accdb`) с дальнейшим просмотром, поиском, редактированием, валидацией и выгрузкой.
- Поддерживаются IO List любых систем (DCS/SIS/GDS) и поставщиков: состав колонок Excel не фиксирован и задаётся маппингом.
- Дополнительно: импорт карты адресации Modbus, связывание сигналов с картой (заполнение M_-полей) и генерация файлов для SCADA (перечень «Тех.объекты», блоки опроса Modbus, экземпляры типовых алгоритмов).

## 2. Работа с базой данных Access

- **Открытие базы:** `.accdb`/`.mdb` через ACE OLE DB; «Файл → Открыть базу данных...» — проверка доступности **до** переключения (при отказе база не переключается, показывается техническая причина).
- **Выбор таблицы:** список таблиц открытой базы; по умолчанию `IO_LIST`; имя таблицы данных произвольное.
- **Создание таблицы с нуля:** структура IO_LIST (130 колонок + уникальный индекс `UX_..._Tag`), имя вводится пользователем; при занятом имени — сообщение; после создания таблица выбирается для записи.
- **Автомиграции:** служебные таблицы (`IO_LIST_Audit`, `MappingTemplates`, `MODBUS_MAP`, `MODBUS_LINK_RULES`, SCADA-таблицы) создаются автоматически; недостающие колонки существующих таблиц добавляются через `ALTER TABLE ADD` (идемпотентно, повтор при следующем обращении при сбое).
- **Устойчивость к недоступной БД:** `DbProbe` — пробное соединение в фоне с жёстким лимитом 5 с; на старте при недоступной базе по умолчанию — сообщение с причиной и предложением выбрать другой файл или выйти; ошибка импорта показывается явным окном; глобальные обработчики необработанных исключений — приложение не закрывается молча.
- **Модель данных:** дерево класса `IOPoint` (Identification, InstrumentTag, Signal, Ranges, Cable, Equipment, Revision + группа `Modbus` (M_-поля) + `Typno`); справочники (`Location`, `System`, `ExType`, коды I/O Type, `Auxiliary`) хранятся строками — enum не используется.
- **Резервная копия:** меню «Таблица → Резервная копия таблицы».

## 3. Импорт IO LIST из Excel (единое окно импорта)

### 3.1 Источник и чтение

- Один файл `.xlsx` за раз: выбор файла («Обзор...» или **drag&drop** в окно), выбор **вкладки (листа)** и **строки заголовка** (по умолчанию 1).
- Пустая ячейка шапки → имя колонки читается из строки выше (двухуровневый заголовок; при строке заголовка 1 не применяется).
- Чтение книги в фоновом потоке — окно не замораживается на файлах 8 МБ+; предпросмотр — первые 50 строк.
- **Документ = файл + вкладка** (`REV_FileName` + `REV_Sheet`): разные вкладки одного файла — разные документы.

### 3.2 Сопоставление столбцов и шаблоны

- Авто-определение связок «столбец Excel ↔ колонка таблицы» (имя + алиасы) + ручная привязка; привязка 1:1, колонка таблицы не может быть привязана дважды (E008).
- Обязательное поле **`Tag`**: без его привязки импорт блокируется.
- Дубликаты заголовков Excel различаются по позиции колонки (отображение «MIN (столбец H)»); шаблоны хранят позицию, старые шаблоны без позиции резолвятся по имени.
- Шаблоны маппинга сохраняются в самой базе (`MappingTemplates`) и **фильтруются по целевой таблице**; для карты Modbus есть встроенный шаблон (§4).

### 3.3 Очистка и нормализация

- Строки, целиком заполненные «-», — пропуск (строки-разделители); «-» в ячейке → NULL.
- Составной код I/O Type (`AIR-EP(3 WIRES)` → `AI-EP`): базовый код, число проводников — в примечание (`column1…column10`).
- Шкалы/уставки: нечисловое значение конвертируется (пробелы, запятая → точка, отсечение единиц); не конвертируется — сохраняется как TEXT + предупреждение W001.
- `Tag` очищается от **всех** пробельных символов (в т.ч. NBSP) при импорте и в карточке: предупреждение W006 + действие `TagCleaned` в аудит.
- Зачёркнутая ячейка `Tag` → строка не импортируется (W005, зачёркивание в предпросмотре); зачёркнутая другая ячейка → NULL.
- Автозаполнение программно (не из Excel): `REV_FileName`/`REV_Sheet`/`REV_RowNumber`/`REV_DateEntered`/`REV_DateModified`/`REV_Author`, `PTag_*` из `Tag`, `Code` = номер строки − 1.

### 3.4 Запись: upsert, идентичность, сессия

- Режимы: **«Добавить (upsert по Tag)»** (по умолчанию) и **«Заменить (очистить)»** (с предупреждением).
- Идентичность **`Tag` + `System` + `Plant`**: существующий тег обновляется только при совпадении System/Plant (Trim, без учёта регистра; пустое входное значение — проверка пропускается, W003); явное различие → критическая ошибка E009, строка игнорируется (запись `CriticalError` в аудит).
- Данные не изменились → ни UPDATE, ни записи в аудит (счётчик «без изменений»); изменились → частичный UPDATE **только по замаппленным колонкам** — немаппленные колонки БД не затираются.
- Одна транзакция на весь файл (ROLLBACK при ошибке); аудит буферизуется и пишется после коммита данных; прогресс UI — не чаще ~10 обновлений/с.

### 3.5 Замена документа

- В режиме «Добавить» при Apply — вопрос «Импортируется новый документ?» (Да / Нет / Отмена); при «Нет» — диалог со **списком документов** (пары «файл :: вкладка») с множественным выбором.
- Отсутствующие в новом файле теги выбранного документа **помечаются к удалению** (`MarkedDelete`, предупреждение W004; строки остаются в БД — физически удаляет пользователь после проверки); красная индикация в истории и выгрузке.
- Выжившие теги переносятся на новый документ (аудит `Update REV_FileName`/`REV_Sheet` с реальным прежним документом); строки других документов и других вкладок не затрагиваются; повторный импорт идемпотентен.

### 3.6 Дубликаты тегов в файле

- Повтор тега (2…9 раз): строка пишется штатным upsert'ом, **все копии тега** (включая первую) дополнительно копируются в `IO_LIST_DublicateTag` (структура IO_LIST без уникального индекса); предупреждение W007 и счётчик.
- Массовый маркер (тег ≥10 повторов) — служебная заглушка: строка не записывается никуда (E005).
- Тег, уже существующий в БД **из другого документа**, → равноправная запись `Duplicate` в аудит (жёлтая, W008; замена документов дублем не считается).

### 3.7 Предпросмотр, отчёт и аудит-галочка

- Предпросмотр с подсветкой: красным — некорректные значения/пустой обязательный тег, зачёркиванием — пропускаемые строки и ячейки, тултипы-подсказки.
- Коды: E001–E009 (ошибки), W001–W008 (предупреждения); отчёт импорта — считано / добавлено / обновлено / без изменений / пропущено разделителей / ошибок, ошибки — с номером строки Excel и кодом.
- Критические события валидации (E002/E003/E004/E005/E009) пишутся в журнал **всегда** — независимо от галочки аудита.
- Галочка «Импорт с аудитом» (по умолчанию включена): выключена → записи в `IO_LIST_Audit` при импорте не создаются (журнал событий работает); ручные операции аудируются всегда.

### 3.8 Тип импорта (профили целевых таблиц)

- Окно импорта универсальное: список **«Тип импорта»** — профиль **IO_LIST** или **MODBUS_MAP**; при смене профиля перестраиваются колонки для привязки, обязательное поле, режимы, строка заголовка, маска листов и список шаблонов, открытый файл перечитывается.
- Пункты меню «Импорт IO LIST из Excel...» и «Импорт Modbus_MAP из Excel...» открывают **одно окно** с предвыбранным профилем.
- Профиль задаётся реестром (колонки, алиасы, обязательное поле, шапка, маска, режимы, встроенный шаблон): новая целевая таблица = новый профиль **без изменения окна**.

## 4. Импорт карты адресации Modbus (профиль MODBUS_MAP)

- Файлы формата «IMCS TO DCS Register Table Modbus» (`.xlsx`): лист `Interface parameters` (станция, Slave ID основной/резервный, скорость, таймаут) + листы `Register Table Function 02/03/06` (шапка — строка 2, колонки A..U).
- Маппинг «столбец Excel ↔ колонка `MODBUS_MAP`» — та же механика, что §3.2: авто-определение по заголовкам (двуязычные «кириллица / English» распознаются по английской строке), ручная привязка, шаблоны с фильтром по таблице, встроенный шаблон «Register Table (стандарт)» — 20 связок B..U (резолв по позиции колонки).
- Обязательное поле — **`PlcTag`**. Служебные колонки (`ID`, `MapFile`, `MapSheet`, `MapRow`, `ObjectTag`, `LinkTag`, `LinkState`) не привязываются — заполняются программой.
- **Маска листов** (по умолчанию «Register Table»; пустая — все листы; `*`/`?` — wildcard, иначе — вхождение подстроки) + галочка «Все листы по маске»: один Apply обрабатывает все листы Function 02/03/06. Лист без колонки `PlcTag` в шапке пропускается с предупреждением.
- Параметры станции читаются с листа `Interface parameters` (первая строка с непустой станцией); если тот же столбец привязан в маппинге листа Register — значение листа Register приоритетнее. `ObjectTag` вычисляется из `PlcTag` (F37).
- **Режим по умолчанию «Сравнение»:** строки сопоставляются по ключу (лист + `PlcTag`, с учётом повторов тега — `#2`, `#3`…): INSERT отсутствующих / UPDATE изменившихся полей / DELETE отсутствующих в файле — одной транзакцией (повтор при блокировке БД).
  - **ID строк сохраняются**, `LinkTag`/`LinkState` не трогаются;
  - `DcsTag` обновляется **только непустым** значением файла — пустое поле файла не затирает связанный/ручной тег;
  - служебные `MapRow`/`ObjectTag` обновляются без аудита.
- Режим **«Заменить строки файла»** — прежнее поведение: все строки файла удаляются и вставляются заново (ID и привязки теряются; окно предупреждает перед выполнением).
- **Аудит** (`TableName=MODBUS_MAP`, `System=Modbus`) одной пачкой после коммита данных: INSERT — по всем заполненным полям (F7.2), UPDATE — по изменённым полям «было → стало», DELETE — одна строка «Строка карты»; сбой аудита пишется в журнал и не прерывает импорт.
- По галочке **«Связать после импорта»** сразу выполняется связывание только пустых связей (§5).
- Итог в окне: счётчики `+добавлено ~обновлено -удалено`, режим, число записей аудита, предупреждения, затем сводка связывания.

## 5. Связывание и адресация Modbus

### 5.1 Связывание IO_LIST ↔ MODBUS_MAP

- **Кандидат объекта ПЛК** из точки: (1) ссылка в скобках `Service`/`ServiceEnglish` («(1110-KM-101A-1)»), (2) ведущее обозначение в `Service`/`ServiceEnglish` с нормализацией P→PM, K→KM и уборкой ведущих нулей, (3) `Loop` с подстановкой классов.
- **Роль сигнала → строка карты:** команды (`DO-COM`/«command:») → Function 06 (общий Control word, все команды объекта — через запятую в `LinkTag`); статусы (fault/running/ready/communication/permitted/emergency/switch/mccb) → Function 02 с суффиксом (`_FAULT/_STA/_REDAY/_TX/_PERMIT/_EM_STOP/_SWITCH_ON/_MCCB POSITION.MCU`); ток (`AI-COM`/«current») → Function 03 `I_A`; роли VFD: `MSC` → «Frequency Setting» (06), `MSI` → «Operating Frequency» (03), run-сигнал → `_STA.MCU`; если Service не распознан — роль по суффиксу тега DCS (`MXA…A/B/C`, `MII`, `MHS`, `MSC`/`MSI`).
- **Многоуровневое сопоставление:** точный `ObjectTag` → префикс «.XX» → базовое устройство → внутри уровня: точный `PlcTag` → `EndsWith("_суффикс")` → ключевые слова роли в `Description` строки карты (с фильтром FuncCode); неоднозначность — первое совпадение в порядке строк карты.
- **Точность:** эквиваленты классов привода (PM↔M, EM↔E, AGM↔AG, BLM↔BL + постепенное удаление букв класса; титул/номер строго); канонизация ведущих нулей (`003A` ↔ `3A`); **семейство объекта** — один сигнал не привязывается к строкам чужого объекта; полное совпадение имени приоритетнее (маркер «привязано не по полным совпадением!»), затем матчинг «максимум букв» с **закреплением** уже совпавших строк (повторный прогон идемпотентен).
- **Фильтр Modbus-сигналов:** обновляются только точки с признаком Modbus в `IO Type` (первая буква `M` или содержит `COM`); иначе — ошибка связывания (аудит `ModbusError`), связь не записывается.
- **Результат:** `LinkTag` (теги РСУ через запятую), `DcsTag` (накопительно через запятую — ручной ввод не затирается, дубли не добавляются), `LinkState` («привязано» / «привязано не по полным совпадением!» / «привязано частично» / «не привязано»).
- Связывание возможно **без импорта файла** — по уже сохранённой карте (для ручных правок в Access); при пустой `MODBUS_MAP` — подсказка сначала импортировать карту.

### 5.2 Ручные правила связывания (маски)

- Таблица `MODBUS_LINK_RULES`: пользовательское сопоставление «поле IO_LIST ↔ поле MODBUS_MAP» дополняет встроенные эвристики (правила приоритетнее).
- Поля правила: `IOField` (Tag/Service/ServiceEnglish/IoType/Loop/SignalType), `MapField` (любое строковое поле карты), **`Mask`**, опциональный фильтр `FuncCode` (02/03/06), `Priority` (меньше — раньше), `Enabled`.
- **Маска:** `{Колонка}` — подстановка значения столбца; `*`/`?` — wildcard (анкорный); `(-N)` — срез N символов справа (если N больше длины — пусто); `(+N)` — взять N символов слева (если N больше — оставить как есть); пустая маска = **полное совпадение** полей. Маска по умолчанию для новых правил — полное совпадение по `Tag`.
- Невалидная маска/поле → правило пропускается с предупреждением в журнале (связывание не падает); выключенное правило (`Enabled=false`) не применяется, но остаётся в БД.
- При совпадении по маске с отклонением (wildcard поглотил символы) → состояние **«привязано частично»** (считается привязанным; полное совпадение побеждает).

### 5.3 Окно «Обновление адресации Modbus согласно MODBUS_MAP» и M_-поля

- Единое окно (меню «Импорт → Обновление адресацию Modbus...», кнопка тулбара «🔗 Modbus адресация») объединяет: обновление связей **полное** (всё пересчитывается, ручные правки теряются — с подтверждением) и **только пустые** (заполненные связи не трогаются), запись M_-полей, редактор правил связывания (добавление/изменение/выключение/удаление + «Проверить») и проверку маски на теге.
- **Обновление адресации (`UpdateAddressing`):** по парам `MODBUS_MAP.DcsTag ↔ IO_LIST.Tag` (список через запятую) в одной сессии заполняются **все `M_*`-поля** с аудитом `Update` по каждому изменённому полю; только для Modbus-сигналов (иначе ошибка «DCSTAG не Modbus сигнала»); тег не найден — счётчик + примеры (≤10); повтор идемпотентен (0 изменений).
- Итоги (счётчики, ошибки ≤10, не найденные) — в окне/инфо-строке; блокировки БД переживаются повторами (`TakeLockWarning`).
- **Глобальный переключатель «Вести аудит (IO_LIST_Audit)»:** выкл. → записи в историю не выполняются (единичные изменения — строка журнала только с именем тега, пакетные — сводная строка со списком тегов ≤20); сообщения связывания в журнал попадают всегда, в историю — только при включённом аудите.

## 6. Чтение, поиск и редактирование

- Чтение: все записи (сортировка по `Area`, `Loop`, `Tag`), точный поиск по `Tag`, подстрочный поиск по `Tag`/`Service`/`Loop`/`InstrumentType` (экранирование `%`, `_`, `[`), фильтр по `System`, количество записей.
- Фильтр «Система» главного окна формируется динамически из БД (`SELECT DISTINCT` + пункт «Все»), перечитывается при обновлении/смене таблицы; ComboBox **редактируемый** — значение можно ввести вручную (точное совпадение без учёта регистра).
- Карточка сигнала: все поля дерева IOclass (включая `Logic`, M_-поля, `Typno`), редактирование и сохранение.
- CRUD: Insert (с возвратом автономера), Update/Delete по ID; уникальность `Tag` (индекс + обработка конфликта); `REV_DateEntered`/`REV_DateModified` проставляются программой.
- Меню «Таблица»: создать таблицу, резервная копия, очистить таблицу (с подтверждением), обновить. Меню «Файл»: выгрузка данных в Excel.

## 7. Валидация

- Обязательность и минимальная длина `Tag`; наличие привязки `Tag` в маппинге (иначе импорт блокируется).
- Пустой обязательный тег — **E002**, строка не записывается.
- Иерархия уставок `LL2 ≤ LL ≤ L ≤ H ≤ HH ≤ HH2` (после конвертации в число) — **E003, не блокирует запись**: строка импортируется, сообщение в отчёт с пометкой «строка будет записана».
- Диапазоны `Range_MIN < Range_MAX` и `Range_MIN2 < Range_MAX2` — **E004, блокирует строку**.
- Справочники (`Location`/`System`/`ExType`/I/O Type/`Auxiliary`) — допустимые значения раздела §9 `IOclass.md` (хранение строками, enum не используется).
- Результат — список ошибок/предупреждений с `Tag`, именем поля и номером строки Excel.

## 8. Интерфейс

- **Главное окно:** список сигналов (только чтение), фильтры — текстовый поиск, система, таблица; инфо-строка; журнал событий снизу (последнее событие сверху, лимит 5000 строк, цвета белый/жёлтый/красный, кнопки «Копировать» и «Очистить»).
- **Меню:** Файл (открыть базу, выгрузить данные в Excel, выход); Импорт («Импорт IO LIST из Excel...», «Импорт Modbus_MAP из Excel...», «Обновление адресацию Modbus...», «История изменений...»); Таблица (создать, резервная копия, очистить, обновить); SCADA (три генератора); Справка (руководство пользователя, «О программе» с версией и разработчиком).
- **Окно истории:** фильтры (тег, поле, действие, документ, вкладка, система, период), колонки контекста (файл/вкладка/система), цветовая индикация (красные — `CriticalError`/`MarkedDelete`/`TagCleaned`/ошибки связывания, жёлтые — `Duplicate`/`ModbusWarning`), внешний горизонтальный ползунок таблицы, кнопки «Показать» / «Выгрузить в Excel...» / «Формирование отчёта...».
- **Справка:** окно краткого руководства (база, импорт, замена, дубликаты, история/отчёты, журнал, поведение при недоступной БД).

## 9. История изменений и отчёты

- Таблица **`IO_LIST_Audit`** той же базы: одна строка на изменённое поле; INSERT — по всем заполненным полям (`OldValue`=NULL), UPDATE — «старое → новое», DELETE (`NewValue`=NULL); действия `CriticalError`, `MarkedDelete`, `TagCleaned`, `Duplicate`, `ModbusWarning`, `ModbusError`.
- **Контекст записи:** документ-источник (`REV_FileName` + `REV_Sheet`), система (`System`), автор (Windows-логин), время; колонки контекста мигрируются в существующие базы автоматически (старые записи — NULL).
- **Выгрузка истории в Excel** с фильтрами (тег, поле, действие, документ, вкладка, система, период); цветовая индикация действий.
- **«Формирование отчёта...»:** SQL-агрегат по документам «файл :: вкладка» × полям со счётчиками по типам изменений (Insert/Update/Delete/CriticalError/MarkedDelete/TagCleaned/Duplicate/ModbusWarning/ModbusError), строки по убыванию «Всего», итоги по документам и общий итог; выгрузка листа «Отчёт».
- История **только читается** из UI (append-only); повторные операции добавляют новые записи со своим `ChangedAt`.

## 10. SCADA — Генерация перечня «Тех.объекты»

- Меню «SCADA → Генерация перечня Modbus (Тех.объекты)...»: файл `.xlsx` (лист `TEHOBJ`, шапка 4 строки, 20 колонок A..T) по образцу «ТехОбъекты_простой.xls».
- Источник — текущая таблица, только точки с заполненной адресацией (`M_PlcTag`; несколько значений через запятую → первое с предупреждением); без адресации — пропуск со счётчиком.
- Заполнение: **Марка** — из выбираемого поля (`Tag` по умолчанию; тире → `_`, ведётся с «_»), **Тип объекта** — `M_DataType` через таблицу соответствия `SCADA_TYPE_MAP` (сид по умолчанию: BOOL→BOOL, 8/16-Bit Signed→INT, 8/16-Bit Unsigned→WORD, 32-Bit Signed→INT, 32-Bit Unsigned→UDINT, 32/64-Bit Floating→REAL; без соответствия — исходный тип + предупреждение), **Наименование** — `Service`, **Описание** — `Loop`, **KKS** — `Tag`, **КОНТРОЛЛЕР/Адрес/№ ресурса** — из M_-полей станции; служебные/пустые колонки — по спецификации.
- Именованные профили настроек окна (сохранение/выбор), панель ошибок и предупреждений (по образцу окна генерации блоков).

## 11. SCADA — Генерация блоков Modbus (XML)

- Меню «SCADA → Генерация блоков Modbus (XML)...»: файл `BufScadaPOUS` XML с блоками опроса Modbus TCP/RTU для импорта в SCADA.
- **XML-шаблон** задаёт структуру целиком: режим «Файл» (путь настройки либо авто-поиск: каталог exe → `Work\` → встроенная копия) или «Код» (хранится в БД `SCADA_MB_TEMPLATE`); кнопка «Проверить шаблон» валидирует (корень `BufScadaPOUS`, есть POU/Blocks, блок мастера) и показывает имя мастера/счётчики.
- **Источник:** точки с `M_PlcTag`; параметры запроса из M_-полей: IP/порт — парсинг `M_SlaveIdMain`, `Mode` = `M_FuncCode` (01–04), `Address` = `M_Address`, ширина по `M_DataType` (BOOL → 1 бит; 8/16 → 1; 32 → 2; 64 → 4 регистра), таймаут — минимум `M_Timeout` по группе; функции записи (06/15/16) пропускаются.
- **Группировка** (IP, порт, код функции) → сортировка по адресу → пакеты по политике: *Contiguous* (разрыв → новый блок), *Cover* (поле min..max), *FixedSize* (по `MaxCount` от начального адреса); лимит Count = min(`MaxCount`, 123 регистров / 246 бит), раздельно для регистров и битов; дедупликация сигналов одного адреса.
- **SlaveId:** правила «станция → SlaveId» (`SCADA_MB_SLAVE_RULES`, таблица редактируется в окне), таблица соответствия типов `SCADA_TYPE_MAP`; параметры станции (IP, протокол, скорость, таймаут) импортируются из IO_LIST.
- **Типовые алгоритмы в блоках:** правило `Typno → шаблон привязок` (`SCADA_TYPNO_MAP`) строго (fallback отключён — предупреждение), шаблоны Data_Out/Data_In (`SCADA_DATAOUT_TEMPLATES`, имя/версия/дата), направление (чтение/запись) — по правилу Typno.
- **Маппинг объектов data-шаблонов** (`SCADA_TEMPLATE_VARS`, скоупы dataout/datain): канал **имени** (колонка IO_LIST или строковый шаблон `{Кол}` → `Info` тега/приёмника/константы) и канала **значения** (литерал → `<IV>`); без маппинга — имя шаблона; неразрешённая колонка/пустой маппинг — предупреждение вместо тихой подстановки; входы мастера пишутся в позиционную строку `<IV>` по карте позиций (SlaveId/TimeOut/Mode/Address/Count/IP/Port), RTU-мастеру IP/порт не пишутся.
- **Объекты мастер-шаблона** (`SCADA_TEMPLATE_VARS`, скоуп `masterobj`, ключ — имя мастер-шаблона; вкладка ① окна, грид «Объекты мастер-шаблона»: Объект / Окончание / Колонка-шаблон / Начальное значение; кнопки «Заполнить из шаблона» и «Сохранить»): список объектов шаблона с токенами имени мастера (`NAME_PACK_TCP_MAINE/RESERVE…`, кроме самих блоков мастера). Имя результата = **автоимя мастера пакета + окончание** (`_MB_X_MAIN` + `.Busy`); пустое окончание — окончание из шаблона (reserve-объект получает имя reserve-блока). Колонка/литерал задают значение: `<IV>` для тегов, `Info`/`T11Text` для констант. Канал имён маппинга data-шаблонов объекты с токенами мастера не переименовывает. **F109:** rec карточки (`ISACARDSINFO`) несёт **базу имени без окончания** — SCADA формирует тег `UPPER(card.Info) + T11Text`, поэтому rec с полным именем давал при импорте удвоение окончания (`_MB_..._MAIN_3.BUSY.Busy`); мастер и его члены `.Busy`/`.Error` делят одну карточку (как в шаблоне SCADA), а объект с двойным окончанием (`_X.BUSY.Busy`) получает базу `_X.BUSY`; маппинг F101 «Окончание» синхронизирует `T11Text` члена, при склейке TCP/RTU общий `cardId` сохраняется.
- **Битовые сигналы:** колонка `M_Bit` (номер бита) — объекты Bit0..Bit15 шаблона заменяются на марку сигнала с соответствующим битом (незаполненные остаются подписями BitN); режимы «Адрес»/«Адрес/бит», галочка «Смещение битов» (`M_Bit_Offset`); default значения — из `Literal`/Typno; запрет зашитого `FALSE` в Info (по умолчанию — имя объекта). **F105:** галочка «Удалять непривязанные битовые объекты (BIT0..BIT15)» (настройка `RemoveUnboundBitObjects`, default выкл): при включённой настройке битовый объект, у которого марка не привязалась (нет точки с нужным `M_Bit` либо у точки пустая `M_Marka`), удаляется из цепочки — блок, связь, подпись `[TEXT]` и карточка не переносятся (предупреждение F105). Объект **сохраняется**, если у него явная строка маппинга (колонка/начальное значение) либо режим «Адрес».
- **Резервирование:** парные блоки main/reserve, токены `{main}/{reserve}` в именах логики, полная копия шаблона на пакет, сиротская логика шаблона размножается по main-пакетам, колонки `M_BusBlockRes`/`M_BusDataOutRes`, разделение data-цепочек по источникам (main/reserve).
- **Именование:** санитизация всех генерируемых имён (спецсимволы, **кроме точки «.»** (F106: точка — нормальный символ, не заменяется), → `_`, двойные `_` → один, предупреждения), токены `{ИмяКолонки}` в паттернах имён блоков/POU, имена блоков = превью, ведущий «_» паттерна не пропускается, POU по шаблону (ID/POUNum из шаблона, холст по bbox).
- **Окно:** разделение на секции (настройки/шаблоны/превью), превью тегов и пакетов отмеченных станций (мастер-detail), гриды станций с галочками «Генерировать» и фильтром станций, красная панель ошибок + журнал, именованные профили настроек, раздвигаемые блоки; производительность (кэш схемы, батч-запросы, диапазонные коллекции).
- **Экспорт:** split-экспорт по файлам с уникальными T11ID/cardId (не переиспользуются), анти-наложение кластеров в файле, кластеризация от локальной позиции пакета, настраиваемый зазор между цепочками, комментарии POU.
- **Обратная запись настроек:** сохранение IP/Port в `M_SlaveIdMain`, обновление SlaveId/Function code/`M_Bit_Offset` в БД по введённым правилам (предупреждение о расхождениях); одна кнопка «Сохранить настройки» (сообщение «Настройки сохранены» при изменениях).
- **Редактор шаблонов:** шаблоны хранятся в БД, единый флоу «файл → окно кода → сохранить в БД» (имя по умолчанию — имя файла); статус генерации/ручное имя/версия шаблона; в превью показывается, какой data-шаблон подходит к Typno и его версия.

## 12. SCADA — Генерация экземпляров типовых алгоритмов

- Меню «SCADA → Генерация экземпляров типовых алгоритмов...»: генерация XML логических схем (корень `BufScadaPOUS`) из XML-шаблона; **экземпляр = контур `Loop`** таблицы IO_LIST.
- Марки сигналов задаются привязками «сигнал шаблона → строка `TYPNO`»; замена марок — маска/суффикс/обрезка/длина (`MarkFor`), кириллица в Loop допустима.
- Хранение в БД: `SCADA_ALGO_SETTINGS` (имя шаблона, `InstancesPerFile` — пагинация экземпляров на файл, `IdStride`, паттерн имени файла, выходной каталог), `SCADA_ALGO_TEMPLATES` (тело шаблона + путь), `SCADA_ALGO_BINDINGS`, `TYPNO`.
- Имена файлов — по паттерну; ID/POUNum уникальны внутри файла (сдвиг по `IdStride`, пагинация), шаблонные ID не переиспользуются.
- Проверки шаблона/привязок (гейты): валидность шаблона, наличие строк TYPNO, корректность привязок — с сообщением об ошибке без частичной генерации.

## 13. Нефункциональные требования

- **Платформа:** Windows 10/11 x64; .NET 8 (WPF); Microsoft Access Database Engine (ACE OLE DB 12.0) на целевой машине.
- **Производительность:** импорт ~1000 строк — до 10 с (одна транзакция на файл); поиск по списку ≤ 1 с; чтение всех записей ≤ 2 с на 10 000 строк.
- **Целостность:** транзакционность импорта (весь файл — одна транзакция либо откат); уникальный индекс по `Tag`.
- **Надёжность:** перехват исключений OleDb с понятными русскими сообщениями; приложение не падает при ошибке БД/файла (лог + диалог); блокировки БД переживаются повторами.
- **Локализация:** интерфейс и журнал — русский; данные — как в источнике.
- **Безопасность:** параметризованные запросы (защита от SQL-инъекций), экранирование спецсимволов LIKE; паролей в БД не используется.

## 14. Ограничения и допущения

- Только Windows + ACE OLE DB (для старых `.mdb` — Jet 4.0); права на файл БД — обычные пользовательские.
- Состав колонок любого IO List задаётся маппингом — фиксированная структура листов не требуется.
- Импорт — **один файл за раз** (на одно нажатие Apply).
- Версионность файлов в БД не ведётся: идентичность документа — файл + вкладка + даты `REV_*`.
- `Logic` хранится одной строкой (полный `Logic No`); отдельные таблицы логик не создаются.
- Шкалы/уставки хранятся как TEXT; числовая интерпретация — только при валидации.
- `MODBUS_MAP` не отображается в списке таблиц главного окна (просмотр — в Access).
- Режим «Заменить строки файла» импорта карты теряет ID строк и привязки `LinkTag`/`DcsTag` (для их сохранения — режим «Сравнение»).
- Выключенный аудит: изменения не пишутся в `IO_LIST_Audit` (остаётся журнал событий с минимизацией).

## 15. Приёмка

- Сборка `dotnet build` (Debug и Release) — **0 ошибок / 0 предупреждений**.
- Смоук-тесты `IO_PJT.Smoke` — **13 основных тестов (+ 10.1), 173 проверки, 0 FAIL** (код выхода 0 — всё OK, 1 — есть FAIL). Внешние файлы не нужны: данные создаются в коде, БД — временная `.accdb` в `%TEMP%`. Каждый тест изолирован (исключение = FAIL теста, остальные продолжаются):
  1. схема БД и реестр колонок (DDL, `FieldRegistry`, идемпотентность создания таблиц);
  2. IO_LIST: upsert (Inserted/Unchanged/Updated/Conflict) и аудит;
  3. импорт карты MODBUS_MAP: чтение, режим «Сравнение» (+/~/−), сохранение ID и привязок, аудит, «Заменить строки файла», блокировка без `PlcTag`;
  4. маски связывания (`MaskPattern`: `&`, `*`, `(±N)`, `Score`, `FindBest`, `Validate`);

  7. генерация XML мастер-блоков: блок на пакет, замена токенов, уникальные T11ID/cardId, невалидный шаблон;
  8. объекты мастер-шаблона: парсинг списка, окончание из шаблона/из маппинга, регресс `..._MAIN.BUSY.Busy`, литерал в `<IV>`, хранение `NameSuffix`; F109: rec карточки = база имени, мастер и члены делят карточку;
