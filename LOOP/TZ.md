### **Техническое задание на разработку программы для автозаполнения и обработки сигналов DCS**

#### **1. Общее описание задачи**
Разработать десктопное приложение с графическим интерфейсом (GUI), предназначенное для автоматического заполнения пустых полей **`Loop`** и **`Typno`** в Excel-файле с перечнем сигналов (`PS_IO_LIST_DCS_v4.xlsx`). Заполнение должно выполняться по строгим правилам, основанным на логике связей сигналов, их типах и атрибутах, с использованием примера из уже заполненного файла (`EBSM_IO_LIST_DCS_v4_пример`). После обработки программа должна добавить столбец **`Status`** для отслеживания изменений.

#### **2. Исходные данные**
1.  **Входной Excel-файл:** `PS_IO_LIST_DCS_v4.xlsx`.
    *   **Структура:** Содержит колонки: `Код`, `Title`, `Title_for_DCS`, `Title_Signal`, `Loop`, `TYPNO`, `Loop No`, `IO Loop No`, `Tag No`, `Service`, `Instrument_Type`, `I/O Type`, `LL`, `L`, `H`, `HH`.
    *   **Ключевые поля для анализа:** `Tag No`, `I/O Type`, `Service`, `LL`, `L`, `H`, `HH`.

2.  **Эталонный пример:** `EBSM_IO_LIST_DCS_v4_пример` (описан в тексте задания).
    *   Примеры правильного заполнения `Loop` и `Typno` для различных типов сигналов (регуляторы, единичные сигналы, клапаны, двигатели и т.д.).

3.  **Целевые поля для заполнения:** `Loop`, `TYPNO`.
4.  **Новое поле для добавления:** `Status` (добавляется после обработки).

---

#### **3. Основные правила формирования значений**

##### **3.1. Формирование поля `Loop`**

1.  **Регуляторы (есть AO сигналы):**
    *   **Источник:** Берется первая часть из общего `Tag No`. Например, для `3101-PT-60003` и `3101-PY-60003A` это `3101`.
    *   **Правило:** Находится общая цифровая часть для всех сигналов контура (например, `60003`).
    *   **Формат:** `<Title>-<Буквенный_Код_ISA>-<Номер_Контура>`.
    *   **Буквенный код ISA:** Формируется из:
        *   **Первая буква:** `P` (давление) для AI, `PD` (перепад давления) для PDT, `F` (расход) для FT, `L` (уровень) для LT, `T` (температура) для TT, и т.д. (основываясь на типе датчика, указанном в `I/O Type` или `Instrument_Type`).
        *   **Вторая буква:** `I` (Indication) — всегда присутствует.
        *   **Третья буква:** `C` (Control) — **обязательно**, если в контуре есть хотя бы один AO-сигнал.
        *   **Четвертая буква:** `A` (Alarm) — добавляется, если для **соответствующего AI-датчика** заданы уставки в колонках `LL`, `L`, `H`, `HH`.
        *   **Пример:** AI `3101-PT-60003` + AO `3101-PY-60003A/B` + уставки (L=0, H=8) → **Loop: `3101-PICA-60003`**.

2.  **Единичные сигналы (без AO):**
    *   **Источник:** `Tag No`.
    *   **Правило:** Значение `Loop` **полностью совпадает** со значением `Tag No` (как в примере `3101-PIA-40003A` для тэга `3101-PT-40003A`).

3.  **Клапаны (On-Off / XV / DIV):**
    *   **Источник:** `Tag No`.
    *   **Правило:** Формируется с префиксами `XV` (On-Off Valve) или `DIV` (Diverter Valve) в соответствии с `Tag No`. В примере: `3107-XV-74507`.

4.  **Сигналы Modbus (`I/O Type` содержит `COM`):**
    *   **Правило:** Поле `Loop` заполняется значением из колонки `IO Loop No` (или `Loop No`), которое уже задано в файле.
    *   **Исключение:** Для этих сигналов поле `Typno` всегда = `COM`.

5.  **Двигатели (Motors):**
    *   **Источник:** `Service` или `IO Loop No`.
    *   **Правило:** К имени добавляется признак `M` (Motor). Например, `3620-P-6607` → `3620-PM-6607`.

6.  **Сигналы с `I/O Type = S` (переключатели, кнопки):**
    *   **Источник:** `IO Loop No`.
    *   **Правило:** `Loop` заполняется значением из колонки `IO Loop No` (пустые строки в примере игнорируются, т.к. они не являются сигналами).

7.  **Прочие сигналы (PLC, DCS, сигналы без категории):**
    *   **Источник:** `IO Loop No` или `Loop No`.
    *   **Правило:** Значение `Loop` берется из существующих колонок `IO Loop No` или `Loop No`, если они не пусты. В противном случае, логика формирования должна быть определена дополнительно (например, на основе `Service`).

---

##### **3.2. Формирование поля `TYPNO`**

1.  **Регуляторы (есть AO сигналы):**
    *   **Источник:** Анализ всех сигналов в контуре.
    *   **Формат:** `PID<Цифры>-<Номер_Алгоритма>R`.
    *   **Цифры:** Четырехзначное число, где каждая цифра — это количество сигналов определенного типа в контуре:
        *   **1-я цифра:** Количество **AI** сигналов.
        *   **2-я цифра:** Количество **AO** сигналов.
        *   **3-я цифра:** Количество **DI** сигналов.
        *   **4-я цифра:** Количество **DO** сигналов.
        *   **Пример:** `PID1200-01R` (где 1 AI, 2 AO, 0 DI, 0 DO).
    *   **Номер алгоритма:** Фиксированный номер (например, `01` или `21`), который должен быть описан в справочнике или определяться по логике (в задании не уточнено, но используется как константа для конкретных контуров).
    *   **Признак резервирования (R):** Добавляется, если в `I/O Type` присутствует признак **R** (например, `AIR(I)-LP`, `DIR-VFC`, `AOR(I)` и т.д.) хотя бы у одного сигнала в контуре.

2.  **Единичные сигналы:**
    *   **Источник:** Тип сигнала.
    *   **Формат:** `<ТипСигнала><Кол-во_в_контуре><Номер_Алгоритма>`.
    *   **Пример:** `AI1000-01` для тэга `3101-PT-40003A`.

3.  **Сигналы Modbus (`I/O Type` содержит `COM`):**
    *   **Правило:** `TYPNO` = `COM`.

4.  **Клапаны (XV, DIV):**
    *   **Источник:** `Tag No`.
    *   **Формат:** `KLPD<Цифры>-<Номер_Алгоритма>`, где `KLPD0021-02` из примера для `3107-XV-64008`.

5.  **Двигатели (Motors):**
    *   **Источник:** `Service` или `IO Loop No`.
    *   **Правило:** Не указано явно, но, вероятно, `Typno` формируется по аналогии с другими единичными сигналами на основе `I/O Type` или остается пустым (если в примере не указано).

6.  **Прочие сигналы:**
    *   **Правило:** Формируется на основе `I/O Type` по аналогии с единичными сигналами, если применимо.

##### **3.3. Добавление столбца `Status`**

*   **Правило:** В новый столбец `Status` для каждой обработанной строки записывается значение **"Ready"**, если для данного сигнала были успешно сформированы и заполнены поля `Loop` и `Typno`.
*   **Цель:** Обеспечить прозрачность обработки и возможность верификации результатов.

#### **4. Функциональные требования к программе**

1.  **Графический интерфейс (GUI):**
    *   Должен быть удобным для работы с файлами Excel.
    *   Обязательные элементы:
        *   Кнопка **"Открыть файл..."** для выбора исходного Excel-файла (`PS_IO_LIST_DCS_v4.xlsx`).

2.  **Алгоритм обработки:**
    *   Загружать данные из выбранного Excel-файла.
    *   Определять контуры (группы сигналов) на основе колонки `IO Loop No`. Это самый надежный признак группировки.

        *   Проанализировать все сигналы.
        *   Если в контуре есть AO-сигналы → это регулятор.
        *   Если в контуре только AI-сигналы → это единичные сигналы.
        *   Применить правила формирования `Loop` и `Typno` для всех сигналов контура.
    *   Заполнить `Loop` и `Typno` только для пустых строк.
    *   Добавить столбец `Status` (если его нет) и заполнить его значением "Ready" для обработанных строк.

3.  **Сохранение результата:**
    *   После обработки программа должна сохранить изменения в новый Excel-файл или перезаписать исходный (по запросу пользователя).
