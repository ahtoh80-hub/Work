# ТЗ: IOListtoDB — импорт таблицы сигналов АСУ ТП из Excel в базу данных Access

**Версия:** 1.0
**Дата:** 30.09.2026
**Исполнитель:** IOListtoDB (WPF, .NET 8)
**Статус:** Draft

---

## 1. Назначение и цель

**Назначение.** Программа предназначена для импорта таблицы сигналов (IO List) систем АСУ ТП из файлов Microsoft Excel (`.xlsx`) в реляционную базу данных Microsoft Access (`.accdb`) с дальнейшим просмотром, поиском, редактированием и выгрузкой данных силами настольного приложения.

**Цель.** Заменить ручную работу с гигантскими таблицами Excel на структурированное хранение в БД с валидацией, справочниками, трассировкой источника и возможностью программной обработки (отчёты, сверки, выгрузки в другие системы: DCS/SIS/GDS, кабельные журналы и т.п.).

**Задачи:**
1. Импортировать файл IO List с учётом двухуровневого заголовка и форматированных разделителей (или задать строку с которой начинается двухуровневый заголовок).
2. Нормализовать данные: убрать служебные строки, заменить «-» на NULL, развернуть составные поля.
3. Считываемые данные IO List файлов записывать в выбранную BD ACCESS (основная таблица IOLIST) по кнопке, если файл базы данных не открыт по кнопке или нет таблицы IOLIST - создать ее. Ключевое поле TAG, если имя тэга совпадает, то запись обновляется по всем полям, если TAG нет такого в таблице IO LIST базы данных ACCESS, то создается новая строка с данными сигнала tagname. Дату записи или обновление записывать в отдельное поле (Создана ДАТА или Обновлено ДАТА).
4. Обеспечить CRUD-доступ из C# (OleDb/ACE)
5. Обеспечить валидацию и трассировку импорта (файл, строка, дата).

## 2. Область данных (предметная область)

**Лист Note (справочники):** Location (Field/DCS/SIS/GDS/ITCC/MMS/MCC/AUX/LCP), I/O Type (TC, HART, DI-VFC, DI-NAMUR, DI-COM, DO-VFC, DO-P, DO-COM, AI-LP, AI-EP, AI-COM, AO, AO-COM + пометки R, (I), S), Auxiliary Instrument (P/B/I/D/R).

**Особенности формата (выявленные при анализе):**
1. Между сигналами — строки-разделители, целиком заполненные «-»: **не импортировать**.
2. «-» в ячейке означает отсутствие значения → **NULL** (не строка «-»).
3. Составной код I/O Type: `AIR-EP(3 WIRES)` → нормализовать до `AI-EP`, число проводников — в примечание.
4. Типы строк: аналоговый сигнал (датчик), цифровой выход (сирена `DOR-P`), интерлок-реле в SIS (`DOR-VFC`).


### F2. Импорт из Excel
- **F2.1** Импортировать лист файла `.xlsx` (проводник выбора файла, поддержка нескольких файлов: D4, C4, I2, …). Указывать номер строки начала заголовка.
- **F2.2** Разбор двухуровневого заголовка (если такой находится): группы `Instrument Range` (14–16), `System Range` (17–19), `Alarm & Interlock Setpoint` (20–24); колонки 1–13, 25–28 — по уровням H1/H2.
- **F2.3** Правила очистки:
  - строки, где все ячейки = «-», пропускать;
  - «-» → NULL;
  - `AIR-EP(3 WIRES)` → `AI-EP` (+ примечание о проводниках).
- **F2.4** Разворачивание `Logic No.` (`Z-00111/00112`) в `refLogic` + `relSignalLogic` с ролью `main` (кол.3) и `setpoint` (кол.27).
- **F2.5** Трассировка: заполнять `SourceRow`, `DocumentName`, `ImportDate` для каждой импортированной записи.
- **F2.6** Отчёт по импорту: считано строк / импортировано / пропущено разделителей / ошибок; ошибки — с номером строки Excel.
- **F2.7** Режимы: «Добавить» (по умолчанию) и «Заменить» (очистить таблицу перед импортом, с предупреждением).

### F3. Чтение и поиск (C#)
- **F3.1** `GetAllAsync()` — все сигналы, упорядоченные по UnitNo, LoopNo, TagNo.
- **F3.2** `GetByTagAsync(tag)` — точный поиск по уникальному тегу.
- **F3.3** `SearchAsync(term)` — подстрочный поиск по TagNo, Service, LoopNo, InstrumentType (экранирование `%`, `_`, `[`).
- **F3.4** `GetBySystemAsync(system)`, `CountAsync()` — фильтр по системе (GDS/DCS/SIS) и количество.

### F4. Редактирование (CRUD)
- **F4.1** `InsertAsync` с возвратом автономера (`SELECT @@identity`).
- **F4.2** `UpdateAsync` по `ID`, `DeleteAsync` по `ID`.
- **F4.3** Запрет дублей `TagNo` (UNIQUE-индекс + обработка ошибки OleDb).

### F5. Валидация данных
- **F5.1** Обязательность и минимальная длина `TagNo`.
- **F5.2** Иерархия тревог: `LL ≤ L ≤ H ≤ HH` (при наличии), единица измерения при заданных уставках.
- **F5.3** Диапазоны: `RangeMin < RangeMax` (приборной пары и системной пары).
- **F5.4** Ссылочная целостность: Location/IoType/AuxInstrument — допустимые значения справочников.
- **F5.5** Результат валидации — список ошибок/предупреждений (по образцу `ValidationResult` из `IOPoint.cs`).

### F6. Просмотр в UI (существующая оболочка)
- **F6.1** Список сигналов с фильтрацией (текстовый поиск, по системе, по юниту).
- **F6.2** Карточка сигнала (все поля, диапазоны, уставки, логики).
- **F6.3** Диалог выбора файла Excel и параметров импорта (по образцу `MappingDialog`/`AccessDialog`).
- **F6.4** Журнал событий (импорт, ошибки, изменения) через `IEventLogger`.

## 5. Нефункциональные требования

- **N1. Платформа:** Windows 10/11 x64; .NET 8 (WPF); Microsoft Access Database Engine (ACE OLE DB 12.0) установлен на целевой машине.
- **N2. Производительность:** импорт файла ~1000 строк — до 10 с; поиск по списку ≤ 1 с; чтение всех записей ≤ 2 с на 10 000 строк.
- **N3. Целостность:** транзакционность импорта одной таблицы (весь файл — одной транзакцией либо откат при ошибке); UNIQUE `TagNo`; FK `relSignalLogic`.
- **N4. Надёжность:** перехват исключений OleDb с понятными сообщениями на русском; приложение не падает при ошибке БД/файла (лог + диалог).
- **N5. Локализация:** интерфейс и журнал — русский; данные — как в источнике (EN).
- **N6. Безопасность:** параметризованные запросы (защита от SQL-инъекций); экранирование спецсимволов LIKE; БД открывается только на чтение/запись приложением (без встроенного пароля).
- **N7. Совместимость:** не ломать существующую функциональность IOPointManager (Excel mapping, Access dialog, InMemoryRepository); новые классы — дополнение, а не замена.

## 7. Критерии приёмки

1. Проект собирается: `dotnet build` — 0 ошибок.
2. `GDS_Schema.sql` выполняется в Access без ошибок; справочники заполнены.
3. Импорт эталонного файла `D4 NKNH21002-1702-ATX.LST-0005_1_EN.xlsx`:
   - количество импортированных сигналов = числу строк-данных листа GDS (без разделителей);
   - тег `2712-GMCT-3001` присутствует, уставки H=10, HH=20, Unit=%LEL;
   - `SourceRow`, `DocumentName`, `ImportDate` заполнены;
   - `relSignalLogic` содержит `Z-00111` и `Z-00112` с ролями `main`/`setpoint`.
4. `GetByTagAsync`, `SearchAsync`, `GetBySystemAsync` возвращают корректные данные.
5. Повторный импорт в режиме «Заменить» не создаёт дублей; в режиме «Добавить» дубль `TagNo` отклоняется с понятным сообщением.
6. Ошибки валидации (нарушение LL≤L≤H≤HH, пустой TagNo) выводятся пользователю.
7. Приложение запускается, окно «IOPoint Manager» работает, события импорта видны в журнале.

## 8. Ограничения и допущения

1. **Допущение:** все файлы IO List имеют одинаковую структуру листов GDS/Note (проверено на выборке файлов проекта НКНХ Sinopec).
2. **Ограничение:** только Windows + ACE OLE DB (OleDb не кроссплатформенный); для старых `.mdb` — Jet 4.0.
3. **Допущение:** код `AIR-EP(3 WIRES)` нормализуется до `AI-EP`; иные составные коды обобщаются правилом «базовый код + примечание».
4. **Ограничение:** ревизии файлов (`Rev`, «frozen version», папки `old/`) — не версионируются в БД автоматически; версионность — через `DocumentName` + `ImportDate`. Полное версионирование (таблица `document` + снапшоты) — отдельная итерация.
5. Лист `Note` может незначительно отличаться между файлами — эталон берётся из `GDS_Schema.sql`.
6. Права на запись в файл БД предполагаются обычными пользовательскими (не требуются права администратора).
