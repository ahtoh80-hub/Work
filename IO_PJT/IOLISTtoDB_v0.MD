# ТЗ: IOListtoDB — импорт таблицы сигналов АСУ ТП из Excel в базу данных Access

**Версия:** 2.0
**Дата:** 10.07.2026
**Исполнитель:** IOListtoDB (WPF, .NET 8)
**Статус:** Draft
**Источник истины:** `IOclass.md` — дерево класса `IOPoint` + раздел Б8 «Маппинг дерева → таблица Access `IO_LIST`»

---

## 1. Назначение и цель

**Назначение.** Программа предназначена для импорта таблиц сигналов (IO List) систем АСУ ТП **произвольной структуры** из файлов Microsoft Excel (`.xlsx`) в реляционную базу данных Microsoft Access (`.accdb`) с дальнейшим просмотром, поиском, редактированием и выгрузкой данных силами настольного приложения. Поддерживаются IO List любых систем (DCS/SIS/GDS) и любых поставщиков — состав колонок Excel не фиксирован и задаётся маппингом (F2.2).

**Цель.** Заменить ручную работу с гигантскими таблицами Excel на структурированное хранение в БД с валидацией, справочниками, трассировкой источника и возможностью программной обработки (отчёты, сверки, выгрузки в другие системы: DCS/SIS/GDS, кабельные журналы и т.п.).

**Задачи:**
1. Импортировать файл IO List с учётом двухуровневого заголовка и форматированных разделителей (или задать строку, с которой начинается заголовок).
2. Нормализовать данные: убрать служебные строки, заменить «-» на NULL, развернуть составные поля.
3. Считываемые данные записывать в выбранную БД ACCESS в таблицу **`IO_LIST`** (структура — раздел Б8 `IOclass.md`, 100 колонок) по кнопке; если файла БД нет или таблицы `IO_LIST` нет — создать их. Ключевое поле **`Tag`** (уникальный индекс `UX_IO_LIST_Tag`): если тег уже есть — запись обновляется по правилу идентичности `Tag`+`System`+`Plant` (F2.8), если нет — создаётся новая строка (upsert). Даты внесения и изменения — в `REV_DateEntered` / `REV_DateModified` (проставляются программой).
4. Обеспечить CRUD-доступ из C# (OleDb/ACE).
5. Обеспечить валидацию и трассировку импорта (файл → `REV_FileName`, строка → `REV_RowNumber`, дата → `REV_DateEntered`).

## 2. Область данных (предметная область)

**Справочники** — единый источник: раздел §9 `IOclass.md` (строки; enum не используется): `Location` (Field/DCS/SIS/GDS/ITCC/MMS/MCC/AUX/LCP/PLC), `System` (DCS/SIS/GDS), `ExType` (Ex.d, Ex.i, …); коды I/O Type (TC, HART, DI-VFC, DI-NAMUR, DI-COM, DO-VFC, DO-P, DO-COM, AI-LP, AI-EP, AI-COM, AO, AO-COM + пометки R, (I), S) — допустимые значения `SignalType`; Auxiliary Instrument (P/B/I/D/R) — поле `Auxiliary`.

**Особенности формата (выявленные при анализе):**
1. Между сигналами — строки-разделители, целиком заполненные «-»: **не импортировать**.
2. «-» в ячейке означает отсутствие значения → **NULL** (не строка «-»).
3. Составной код I/O Type: `AIR-EP(3 WIRES)` → нормализовать до `AI-EP`, число проводников — в примечание (одно из `column1…column10` через маппинг).
4. Типы строк: аналоговый сигнал (датчик), цифровой выход (сирена `DOR-P`), интерлок-реле в SIS (`DOR-VFC`).
5. Состав колонок зависит от поставщика файла — целевое соответствие задаётся в окне сопоставления (F2.2).


### F1. Работа с базой данных Access
- **F1.1** Открытие файла `.accdb`/`.mdb` (провайдер ACE/Jet), проводник выбора файла.
- **F1.2** **Выбор таблицы** из списка существующих таблиц открытой базы; по умолчанию — `IO_LIST`; имя таблицы может быть любым.
- **F1.3** **«Создать таблицу с нуля»** — по структуре раздела Б8 `IOclass.md` (100 колонок + уникальный индекс `UX_IO_LIST_Tag`): имя вводится пользователем (по умолчанию `IO_LIST`); при занятом имени — сообщение; после создания таблица автоматически выбирается для записи. Если в открытой базе нет служебных таблиц (`IO_LIST_Audit`, `MappingTemplates`) — они создаются автоматически при первой записи; недостающие колонки существующей таблицы добавляются автоматически (`ALTER TABLE ADD`).

### F2. Импорт из Excel
- **F2.1** Импортировать лист(ы) файла `.xlsx`: **при открытии выбирать вкладку (лист)** и **строку начала чтения** (первая строка — названия столбцов, по умолчанию строка 1); поддержка нескольких файлов.
- **F2.2** **Авто-определение + окно сопоставления «столбцы Excel ↔ колонки выбранной таблицы Access»:** заголовки Excel определяются автоматически, совпадения имён предлагаются автоматически; ручная привязка — кнопка Bind, запись — Apply, сохранение шаблона. **Номера колонок — только подсказка для эталонного файла** (Instrument Range 14–16, System Range 17–19, Alarm & Interlock Setpoint 20–24; колонки 1–13, 25–28 — по уровням H1/H2), а не требование к импорту. Двухуровневый заголовок учитывается при обнаружении. **Обязательное минимальное поле — `Tag`: без привязки `Tag` Apply/импорт блокируется (ошибка в журнале).**
- **F2.3** Правила очистки:
  - строки, где все ячейки = «-», пропускать;
  - «-» → NULL;
  - `AIR-EP(3 WIRES)` → `AI-EP` (+ примечание о проводниках — в одно из `column1…column10`);
  - `Ex.d`/`Ex.i`/… записываются как есть (без конвертации; enum не используется);
  - **шкалы и уставки:** если значение в Excel **не в формате Decimal** — конвертировать (удалить пробелы, заменить запятую на точку, отбросить нечисловые примеси-единицы); не конвертируется — сохранять исходный текст как есть (колонки TEXT) и выдать предупреждение в отчёте.
- **F2.4** Колонка `Logic No.` (`Z-00111/00112/…`) записывается целиком в поле **`Logic`** (`Identification`, `TEXT(255)`); отдельные таблицы логик (`refLogic`/`relSignalLogic`) **не создаются**.
- **F2.5** Трассировка и автозаполнение (программно, не из Excel):
  - `REV_FileName` — имя открытого файла; `REV_Sheet` — имя вкладки (листа)-источника (F2.16);
  - **`REV_RowNumber` — номер строки Excel, в которой находится `Tag`** (присваивается автоматически, маппингом не переопределяется);
  - `REV_DateEntered` / `REV_DateModified` — момент вставки / изменения;
  - `REV_Author` — Windows-логин (`домен\логин`); `Code` = `REV_RowNumber − 1`, если колонка Excel с `Code` не сопоставлена;
  - `PTag_*` — вычисляются из `Tag`;
  - каждое действие фиксируется в `IO_LIST_Audit` (F7).
- **F2.6** Отчёт по импорту: считано строк / импортировано / обновлено / пропущено разделителей / ошибок; ошибки — с номером строки Excel и кодом ошибки; события — в журнал (белый — норма, жёлтый — предупреждение, красный — ошибка).
- **F2.7** Режимы: **«Добавить» = upsert по `Tag`** (по умолчанию; условия обновления — F2.8) и **«Заменить»** (очистить таблицу перед импортом, с предупреждением). **Повтор тега внутри одного Excel-файла — ошибка** с номерами обеих строк. **Галочка «Импорт с аудитом»** (по умолчанию включена): выключена → записи в `IO_LIST_Audit` не выполняются (включая критические), события журнала окна сохраняются; ручные операции (карточка, удаление) аудируются всегда.
- **F2.8** **Правило идентичности и отсечение неизменённого (`Tag` + `System` + `Plant`):**
  - существующий в БД `Tag` обновляется, только если `System` и `Plant` совпадают с импортируемыми (Trim, без учёта регистра); **пустое входное значение = проверка пропускается** → предупреждение `W003` (конфликт только при явном различии обоих заданных значений);
  - различие → **критическая ошибка**: строка игнорируется, в `IO_LIST_Audit` пишется `CriticalError` (значения БД → Excel), в отчёт — код `E009`;
  - если данные полей **не изменились** → **ни UPDATE, ни записи в аудит** (счётчик «без изменений» в отчёте);
  - если изменились → **частичный `UPDATE` только по изменившимся полям** (+служебные `REV_*`/`PTag_*`) и аудит только по ним;
  - новое поле **`Plant`** входит в `Identification` (структура Б8 — 100 колонок) и участвует в сравнении вместе с `System`.

- **F2.9** **Сессия массовой записи (производительность импорта):** импорт выполняется в **одной сессии БД** — одно соединение + одна транзакция на весь файл (вместо открытия соединения и транзакции на каждую строку); данные фиксируются одним `COMMIT` в конце (`EndSession`), при ошибке — `ROLLBACK` всего импорта (`AbortSession`, идемпотентно). Записи аудита (`IO_LIST_Audit`) в режиме импорта **буферизуются в памяти** (`BeginBatch`) и пишутся одной транзакцией после коммита данных (`EndBatch`); при отмене буфер отбрасывается (`DiscardBatch`) — при ошибке импорта в БД не попадает ни данных, ни аудита. Ручные операции (карточка, удаление, очистка вне импорта) работают вне сессии — по одному соединению. Построчные события журнала и `Info`-сообщения по каждой строке **подавляются** в сессии (сводка — по завершении импорта); прогресс UI обновляется не чаще ~10 раз/с. Целевой эффект: импорт ~1300 строк — секунды вместо минут.

- **F2.10** **Сравнение только по замаппленным колонкам (F2.8):** при upsert частичное обновление (`ComputeDataChanges`) сравнивает **только колонки, привязанные к Excel** (плюс программно заполняемое `Code`); колонка, не имеющая привязки в маппинге импорта, **не считается изменением** и её значение в БД сохраняется (ранее немаппленная колонка читалась как `null` и затирала заполненное поле БД). Ручные операции (карточка, `Update`) сравнивают все поля — точка приходит целиком из формы.

- **F2.11** **Замена документа (новый документ / новая версия файла):**
  - при нажатии **Apply** в режиме «Добавить (upsert)» выводится вопрос **«Импортируется новый документ?»** (`Да` / `Нет` / `Отмена`): `Да` — штатный импорт (поведение без изменений); `Отмена` — импорт не выполняется;
  - при `Нет` открывается диалог **«Взамен какого документа?»** со списком документов целевой таблицы (**пары «файл + вкладка»**: `SELECT DISTINCT REV_FileName, REV_Sheet`, непустые файлы; отображение «файл :: вкладка», старые записи без вкладки — «файл (без вкладки)»); пустой список → предупреждение, замена невозможна; отмена диалога → импорт не выполняется;
  - импорт выполняется с параметрами `ImportOptions.ReplacedFileName` + `ImportOptions.ReplacedSheet` (файл и вкладка заменяемого документа):
    - **новые/переименованные теги** (нет в БД) — вставка штатным upsert (изменение `Tagname` = старый тег помечается, новый добавляется);
    - **теги заменяемого документа, присутствующие в новом файле** — обновляются upsert'ом, их `REV_FileName` и `REV_Sheet` переносятся на новый документ (аудит `Update` по `REV_FileName`, а при смене вкладки — дополнительно по `REV_Sheet`; линовка версий документа сохраняется);
    - **теги заменяемого документа, отсутствующие в новом файле** — **пометка без физического удаления**: `REV_Description` = «Удаляются, отсутствуют в последней версии файла <имя нового файла>», `REV_DateModified` = now; в `IO_LIST_Audit` пишется действие **`MarkedDelete`** (поле `REV_Description`, старое → новое), в отчёт — предупреждение **`W004`** и счётчик «помечено к удалению»; строки **остаются в БД** — физическое удаление выполняет пользователь после проверки;
    - сравнение ведётся **только по строкам выбранного документа — пары «`REV_FileName` + `REV_Sheet`»** (F2.16); строки других документов **и другие вкладки того же файла** не затрагиваются; документ без вкладки (старые записи, `REV_Sheet` IS NULL) матчится только с позицией «без вкладки»;
    - **красная индикация:** записи `MarkedDelete` отображаются красным в окне истории (F7.5) и при выгрузке аудита в Excel (красный шрифт), в журнале событий — красными строками «помечен к удалению (необходимо удалить из БД)»;
  - режим «Заменить (очистить)» и вопрос/диалог не используются (таблица очищается целиком);
  - повторный импорт того же файла как замена самому себе (`ReplacedFileName` = имя нового файла **и та же вкладка** `ReplacedSheet`) — служебный перенос `REV_FileName`/`REV_Sheet` не выполняется (идемпотентность), пометка отсутствующих тегов — выполняется.

- **F2.12** **Зачёркнутые строки Excel (правило отсечения):** строка, в которой ячейка **`Tag` зачёркнута** (шрифт с зачёркиванием в ячейке Excel), **исключена из проекта**: не импортируется, **не попадает в БД**, её тег **не регистрируется** среди обработанных (`seenTags`) — при замене документа (F2.11) такой тег помечается как отсутствующий в новой версии. В отчёт — предупреждение **`W005`** + счётчик «зачёркнутых пропущено», в журнал — предупреждение по каждой строке (номер строки + текст тега) и итоговый перечень зачёркнутых тегов. Если зачёркнута **другая ячейка** (не `Tag`) — её значение считается **пустым (`NULL`)**, как при «-» (F2.3). Зачёркнутые строки и ячейки **подсвечены зачёркиванием в предпросмотре** окна импорта (тултип «строка не будет импортирована» / «значение не будет импортировано»). Гарантия журнала (Задание п.8): **каждая критическая ошибка валидации** (`E002`/`E004`/`E005`/`E009`, а также `E003` — иерархия уставок, не блокирующая запись) пишется в журнал событий **немедленно и всегда** — журнал не зависит от галочки «Импорт с аудитом» (при выключенном аудите данные в `IO_LIST_Audit` не пишутся, но все красные события журнала сохраняются).

- **F2.13** **Пустая ячейка шапки → строка выше:** если ячейка строки заголовка (`HeaderRow`) пуста, имя колонки читается из ячейки `(HeaderRow − 1)` той же колонки (двухуровневый заголовок эталонного файла); при `HeaderRow = 1` fallback не применяется. Пустое имя после fallback остаётся пустым — колонка без имени в маппинг не попадает.
- **F2.14** **Дубликаты заголовков Excel → разные колонки таблицы:** каждая привязка несёт 0-based позицию колонки `ColumnMap.ExcelColumnIndex` (в шаблонах — тоже; старые шаблоны без индекса резолвятся по имени). Отображение в окне маппинга — **«MIN (столбец H)»**. `AutoDetect` проставляет индексы всем строкам и подсказку о дубликате (`заголовок встречается N раз — колонка определяется позицией`): первое вхождение имени получает авто-привязку, повторные — нет (E008-страховка). При импорте/в предпросмотре колонка резолвится по позиции (совпадает ли в этой колонке ожидаемое имя), иначе — по имени. Уникальность колонок таблицы (E008, привязка 1:1) сохраняется.
- **F2.15** **Очистка `Tag` от пробелов:** из значения `Tag` удаляются **все** пробельные символы (включая NBSP `\u00A0`) — в импорте (до `PTag_*`-автозаполнения, валидации и upsert) и в карточке (до проверки обязательности). Изменение фиксируется: предупреждение **`W006`** в отчёте/журнале + действие **`TagCleaned`** в `IO_LIST_Audit` (старое → новое значение, отображается **красным** в окне истории и при выгрузке) с контекстом «файл + вкладка + система». При выключенной галочке «Импорт с аудитом» запись `TagCleaned` не выполняется (как весь аудит импорта).
- **F2.16** **Документ = файл + вкладка:** идентификация документа в БД — пара `REV_FileName` + `REV_Sheet` (имя вкладки-источника; колонка добавлена в дерево, тип `TEXT(255)`, автозаполнение как `REV_FileName`; существующие таблицы мигрируются `ALTER TABLE ADD` через `EnsureColumns`). Разные вкладки одного файла — **разные документы**: сигналы вкладок разделяются, замена документа (F2.11) работает строго в пределах выбранной пары, строки других вкладок не затрагиваются. Идентичность `Tag`+`System`+`Plant` (F2.8) и уникальность `UX_..._Tag` не меняются: один тег — одна запись, `REV_Sheet` обновляется при импорте/переносе документа. `REV_Sheet` входит в авто-колонки (маппингом не переопределяется) и в контекст аудита (F7.7).

### F3. Чтение и поиск (C#)
- **F3.1** `GetAllAsync()` — все сигналы, упорядоченные по `Area`, `Loop`, `Tag`.
- **F3.2** `GetByTagAsync(tag)` — точный поиск по уникальному тегу `Tag`.
- **F3.3** `SearchAsync(term)` — подстрочный поиск по `Tag`, `Service`, `Loop`, `InstrumentType` (экранирование `%`, `_`, `[`).
- **F3.4** `GetBySystemAsync(system)`, `CountAsync()` — фильтр по `System` (DCS/SIS/GDS) и количество.

### F4. Редактирование (CRUD)
- **F4.1** `InsertAsync` с возвратом автономера (`SELECT @@identity`); при вставке — `REV_DateEntered`.
- **F4.2** `UpdateAsync` по `ID`, `DeleteAsync` по `ID`; при обновлении — `REV_DateModified`.
- **F4.3** Уникальность тега: индекс `UX_IO_LIST_Tag` + обработка ошибки OleDb.

### F5. Валидация данных
- **F5.1** Обязательность и минимальная длина `Tag`; наличие привязки `Tag` в маппинге (без неё импорт блокируется — F2.2).
- **F5.2** Иерархия тревог: `LL2 ≤ LL ≤ L ≤ H ≤ HH ≤ HH2` — проверяется **после конвертации** значений в число (F2.3); единицы измерения не хранятся и не проверяются; неконвертируемое значение — предупреждение (значение сохранено как есть, TEXT). Нарушение иерархии (`E003`) — **не блокирует запись**: строка импортируется в БД (в т.ч. из-за «0 = уставка не задана» в SIS-файлах), сообщение попадает в отчёт/список ошибок с пометкой «строка будет записана».
- **F5.3** Диапазоны: `Range_MIN < Range_MAX` и `Range_MIN2 < Range_MAX2` — после конвертации (F2.3); иначе ошибка `E004` — строка **не записывается**.
- **F5.4** Ссылочная целостность: `Location`/`System`/`ExType`/`IoType`/`Auxiliary` — допустимые значения справочников §9 `IOclass.md` (хранение строками).
- **F5.5** Результат валидации — список ошибок/предупреждений с указанием `Tag` и имени поля (структура `ValidationResult` — в разделе §6).

- **F6.2** Карточка сигнала (все поля дерева `IOclass`, включая `Logic`; диапазоны, уставки).

### F7. История изменений и выгрузка в Excel
- **F7.1** Каждое **добавление** и **изменение каждого поля** фиксируется в служебной таблице той же базы **`IO_LIST_Audit`**:

| Колонка | Тип | Описание |
|---|---|---|
| `ID` | COUNTER PK | автономер записи истории |
| `TableName` | TEXT(255) | имя затронутой таблицы (напр. `IO_LIST`) |
| `Tag` | TEXT(255) | тег записи |
| `ChangeAction` | TEXT(50) | `INSERT` / `UPDATE` / `DELETE` / `CriticalError` / `MarkedDelete` / `TagCleaned` (имя `Action` — зарезервировано Access) |
| `FieldName` | TEXT(255) | имя колонки |
| `OldValue` | TEXT(255) | старое значение (NULL при INSERT) |
| `NewValue` | TEXT(255) | новое значение (NULL при DELETE) |
| `REV_FileName` | TEXT(255) | **F7.6:** документ-источник изменения (из какого Excel-файла инициировано; NULL для старых/ручных записей) |
| `REV_Sheet` | TEXT(255) | **F7.7:** вкладка-источник изменения (документ = файл + вкладка, F2.16; NULL для старых/ручных записей) |
| `System` | TEXT(255) | **F7.6:** система изменения (`DCS`/`SIS`/`GDS`) |
| `ChangedBy` | TEXT(255) | Windows-логин (`домен\логин`) |
| `ChangedAt` | DATETIME | момент изменения (системные часы) |

```sql
CREATE TABLE IO_LIST_Audit (
  ID COUNTER PRIMARY KEY,
  TableName TEXT(255), Tag TEXT(255), ChangeAction TEXT(50),
  FieldName TEXT(255), OldValue TEXT(255), NewValue TEXT(255),
  REV_FileName TEXT(255), REV_Sheet TEXT(255), System TEXT(255),
  ChangedBy TEXT(255), ChangedAt DATETIME
);
```

> Существующие таблицы аудита **мигирируются автоматически**: при отсутствии `REV_FileName`/`REV_Sheet`/`System` выполняется `ALTER TABLE [IO_LIST_Audit] ADD COLUMN … TEXT(255)` (`ServiceSchema.EnsureServiceTables` через `Schema.AuditContextColumns`, идемпотентно); старые записи получают NULL.

- **F7.2** Формат: «что на что менялось» — одна строка на изменённое поле; добавление записи — строки по всем заполненным полям (`ChangeAction=INSERT`, `OldValue`=NULL); удаление — `ChangeAction=DELETE`, `NewValue`=NULL.
- **F7.3** **Экспорт истории в Excel** (`.xlsx`): фильтры по `Tag`, дате, полю, действию, **документу (`REV_FileName`)**, **вкладке (`REV_Sheet`, F7.7)** и **системе (F7.6)**; кнопка «Выгрузить в Excel» в окне истории; в выгрузку включены колонки «Файл (REV_FileName)», «Вкладка (REV_Sheet)» и «Система».
- **F7.4** История только читается из UI (редактирование и удаление строк истории запрещены); экспортируются также текущие данные репозитория (отчёт по п. F6.1).
- **F7.5** Записи `CriticalError` (конфликт идентичности System/Plant, F2.8), `MarkedDelete` (пометка на удаление при замене документа, F2.11) и `TagCleaned` (очистка `Tag` от пробелов, F2.15) отображаются в окне истории красным; при выключенной галочке «Импорт с аудитом» записи истории на время импорта не выполняются.
- **F7.6** **Контекст изменения (документ + система):** каждая запись аудита несёт `REV_FileName` (инициирующий документ: имя импортируемого файла; для `MarkedDelete`/переноса выживших — **новый** файл) и `System` (система затронутой/импортируемой записи). Источники: `IoPoint.Revision.FileName` / `IoPoint.Identification.System` при импорте и ручных операциях; для `MarkMissingTagsForDeletion` — `System` читается из БД. Окно истории: **колонки «Файл» и «Система»** + **фильтры по ним** (подстрока, `LIKE`); в `GetHistory` — параметры `fileName`/`system`. Для записей без известного контекста (`Clear`, старые записи) — NULL.
- **F7.7** **Контекст вкладки (файл + вкладка = документ):** каждая запись аудита дополнительно несёт `REV_Sheet` — имя вкладки-источника (`options.SheetName` / `IoPoint.Revision.Sheet`); для `MarkMissingTagsForDeletion` — новая вкладка документа. Окно истории: **колонка «Вкладка»** + **фильтр по ней** (подстрока, `LIKE`); в `GetHistory` — параметр `sheet`; в выгрузке Excel — колонка «Вкладка (REV_Sheet)». Существующие таблицы аудита мигрируются автоматически (`Schema.AuditContextColumns` += `REV_Sheet`, ALTER TABLE ADD); старые записи — NULL. Связка с F2.16: одна и та же запись истории всегда указывает на ту же пару «файл + вкладка», что и данные `IO_LIST`.
- **F7.8** **Формирование отчёта (сводка по документам):** кнопка «Формирование отчёта...» в окне истории (рядом с «Выгрузить в Excel...») открывает окно отчёта. Данные — SQL-агрегат `AuditService.GetSummary`: `SELECT REV_FileName, REV_Sheet, FieldName, ChangeAction, COUNT(*) … GROUP BY …` (**те же фильтры**, что в окне истории; считается вся таблица аудита, а не только отображаемые 500 записей `GetHistory`). Построение строк — `ReportBuilder.Build`: для каждого документа «файл :: вкладка» — по каждой ячейке (полю) счётчики по типам изменений (`Insert`/`Update`/`Delete`/`CriticalError`/`MarkedDelete`/`TagCleaned`) и «Всего» (напр. `Service: 56`), строки сортируются по убыванию «Всего», затем — полужирная строка-итог документа «ИТОГО» и общая строка «ВСЕГО»; внизу окна — «Документов: N · Всего изменений: M», в шапке — условие отбора (текущие фильтры). Документы с NULL: «(без файла)», «(без вкладки)». Выгрузка — `ExcelExportService.ExportAuditReport` (лист «Отчёт»: заголовок + условие отбора, таблица с теми же колонками, итоги — полужирным с заливкой). Открытие окна — через хук `HistoryViewModel.OpenReport` (MVVM, VM не ссылается на Views).

## 5. Нефункциональные требования

- **N1. Платформа:** Windows 10/11 x64; .NET 8 (WPF); Microsoft Access Database Engine (ACE OLE DB 12.0) установлен на целевой машине.
- **N2. Производительность:** импорт файла ~1000 строк — до 10 с; поиск по списку ≤ 1 с; чтение всех записей ≤ 2 с на 10 000 строк.

- **N7. Актуальность кода:** код предыдущих итераций (`GdsSignal`, набор IOPointManager) **не актуален** (решение п.3.4) — разработка ведётся заново по `IOclass.md`; существующий каркас `IO_PJT` (WinForms) переиспользуется как референс, но ПО создаётся в WPF.

## 7. Критерии приёмки

1. Проект собирается: `dotnet build` — 0 ошибок.
2. Таблица `IO_LIST` создаётся в Access по DDL из раздела Б8 `IOclass.md` без ошибок; валидация справочников §9 проходит.
3. Импорт эталонного файла `_Specification\пример данных.xlsx` (лист `OSBL_IO_List_SCS_v4`; дополнительно — `D4 NKNH21002-1702-ATX.LST-0005_1_EN.xlsx` как второй профиль):
   - количество импортированных сигналов = числу строк-данных листа (без разделителей);
   - тег `2701-XZY-10101A` присутствует: `System`=SIS, `SignalType`=DOR-P, `ExType`=Ex.d, `Logic`=2701-Z-10001/2701-Z-10004/2701-Z-10101;
   - для аналогового сигнала (тестовые данные): уставки `H`=10, `HH`=20 записаны в колонки `H`/`HH` (единицы измерения не хранятся);
   - `REV_RowNumber`, `REV_FileName`, `REV_DateEntered` заполнены.
4. `GetByTagAsync`, `SearchAsync`, `GetBySystemAsync` возвращают корректные данные.
5. Повторный импорт в режиме «Заменить» не создаёт дублей; режим «Добавить» обновляет существующий тег (upsert) и вставляет новый; повтор тега внутри одного файла — ошибка с номерами строк.
6. Ошибки валидации (нарушение `LL2 ≤ LL ≤ L ≤ H ≤ HH ≤ HH2`, пустой `Tag`, `Range_MIN ≥ Range_MAX`) выводятся пользователю с указанием `Tag` и поля.
7. Приложение запускается (WPF), главное окно работает, события импорта видны в журнале (белый/жёлтый/красный).
8. Таблица, созданная «с нуля» (F1.3), содержит все 100 колонок и индекс `UX_IO_LIST_Tag`; проверен импорт в таблицу с произвольным именем (не только `IO_LIST`); в базе без служебных таблиц `IO_LIST_Audit`/`MappingTemplates` создаются автоматически при записи.
9. Импорт без привязки `Tag` блокируется с ошибкой в журнале; неверно выбранная вкладка/строка заголовка — понятное сообщение с номером строки.
10. История: после импорта и редактирования `IO_LIST_Audit` содержит INSERT/UPDATE/DELETE со значениями «старое → новое»; выгрузка в `.xlsx` открывается в Excel.
11. **Правило идентичности (F2.8):** повторный импорт без изменений → счётчик «без изменений», записи в `IO_LIST_Audit` не прибавляются; существующий `Tag` с другими `System`/`Plant` → строка не изменена, в истории `CriticalError`, в отчёте код `E009`; импорт с выключенной галочкой «Импорт с аудитом» не создаёт записей истории (события журнала сохраняются).
11. Нечисловая шкала/уставка (напр. `<50`, `20±1`) сохраняется без потерь (TEXT) и даёт предупреждение валидации; числовые значения конвертируются и проходят проверку иерархии F5.2.
12. **Замена документа (F2.11/F2.16):** Apply в режиме «Добавить» спрашивает «Импортируется новый документ?»; при «Нет» предлагается список документов — **пары «файл + вкладка»** (`SELECT DISTINCT REV_FileName, REV_Sheet`, отображение «файл :: вкладка»); отсутствующие в новом файле теги **выбранной пары** помечены в `REV_Description` (остались в БД), в истории — `MarkedDelete` красным, в отчёте — предупреждения `W004` и счётчик «помечено к удалению»; строки других документов **и других вкладок того же файла** не затронуты; выжившие теги получают новую пару `REV_FileName`+`REV_Sheet` (+аудит Update, при смене вкладки — и по `REV_Sheet`); «Отмена»/отмена диалога — импорт не выполняется.
13. **Пустая шапка (F2.13):** при `HeaderRow = 2` и пустой ячейке заголовка имя колонки читается из строки 1 той же колонки; при `HeaderRow = 1` fallback не применяется.
14. **Дубликаты заголовков (F2.14):** лист с дважды встречающимся `MIN` даёт две строки маппинга с отображением «MIN (столбец …)» и подсказкой о дубликате; привязка `MIN`→`Range_MIN` и второй `MIN`→`Range_MIN2` импортирует значения из **разных** колонок Excel (резолв по позиции); старый шаблон без индекса загружается и резолвится по имени.
15. **Очистка Tag (F2.15):** `Tag` со вложенными пробелами/NBSP записывается без пробелов; в отчёте `W006`, в истории запись `TagCleaned` красным с контекстом «файл + вкладка + система»; в карточке сохранение также чистит `Tag`.
16. **Документ = файл + вкладка (F2.16/F7.7):** после импорта вкладки файла в `REV_Sheet` записано имя вкладки; импорт двух вкладок одного файла даёт два документа; `GetDocuments` возвращает обе пары; существующая база без `REV_Sheet` мигрирует автоматически (`ALTER TABLE ADD`), старые записи — NULL и матчатся с документом «без вкладки»; окно истории содержит колонку и фильтр «Вкладка», выгрузка Excel — колонку «Вкладка (REV_Sheet)».
17. **Формирование отчёта (F7.8):** кнопка «Формирование отчёта...» в окне истории открывает окно отчёта: по каждому документу «файл :: вкладка» — по каждой ячейке количество изменений по типам и «Всего» (напр. `Service: 56`), строки «ИТОГО» по документу и «ВСЕГО» равны сумме строк; отчёт учитывает текущие фильтры окна истории и считает **всю** таблицу аудита (сверка: при >500 записей истории итог отчёта не совпадает с `Records.Count`, но равен `COUNT(*)` по фильтру); внизу — «Документов: N · Всего изменений: M»; «Экспорт в Excel...» формирует `.xlsx`, где числа и итоги совпадают с экраном.

## 8. Ограничения и допущения

1. **Допущение:** состав колонок любого IO List задаётся маппингом в окне сопоставления (авто-определение + ручное уточнение); фиксированная структура листов не требуется.
2. **Ограничение:** только Windows + ACE OLE DB (OleDb не кроссплатформенный); для старых `.mdb` — Jet 4.0.
3. **Допущение:** код `AIR-EP(3 WIRES)` нормализуется до `AI-EP`; иные составные коды обобщаются правилом «базовый код + примечание» (примечание — в `column1…column10`).
4. **Ограничение:** ревизии файлов (`Rev`, «frozen version», папки `old/`) — не версионируются в БД автоматически; версионность — через `REV_FileName` + `REV_DateEntered`. Полное версионирование (таблица `document` + снапшоты) — отдельная итерация.
5. Справочники берутся из раздела §9 `IOclass.md` (строки); `GDS_Schema.sql` как эталон не используется (см. «История / архив v0»).
6. Права на запись в файл БД предполагаются обычными пользовательскими (не требуются права администратора).
7. **Допущение:** `Logic` хранится одной строкой (полный `Logic No`); разбиение на отдельные логики и роли (main/setpoint) — вне объёма v0.
8. **Допущение:** шкалы и уставки хранятся как TEXT (нечисловые данные не теряются); числовая интерпретация — только при валидации (F5.2/F5.3) по правилам конвертации F2.3.
9. **Допущение:** история изменений ведётся в служебной таблице `IO_LIST_Audit` той же базы; выгрузка истории — в Excel (F7).
