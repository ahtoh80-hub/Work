# ТЗ: IOListtoDB — импорт таблицы сигналов АСУ ТП из Excel в базу данных Access

**Версия:** 2.0
**Дата:** 10.07.2026
**Исполнитель:** IOListtoDB (WPF, .NET 8)
**Статус:** Draft
**Источник истины:** `IOclass.md` — дерево класса `IOPoint` + раздел Б8 «Маппинг дерева → таблица Access `IO_LIST`»

---

## 1. Назначение и цель

**Назначение.** Программа предназначена для импорта таблиц сигналов (IO List) систем АСУ ТП **произвольной структуры** из файлов Microsoft Excel (`.xlsx`) в реляционную базу данных Microsoft Access (`.accdb`) с дальнейшим просмотром, поиском, редактированием и выгрузкой данных силами настольного приложения. Поддерживаются IO List любых систем (DCS/SIS/GDS) и любых поставщиков — состав колонок Excel не фиксирован и задаётся маппингом (F2.2).

**Цель.** Заменить ручную работу с гигантскими таблицами Excel на структурированное хранение в БД с валидацией, справочниками, трассировкой источника и возможностью программной обработки (отчёты, сверки, выгрузки в другие системы: DCS/SIS/GDS, кабельные журналы и т.п.).

**Задачи:**
1. Импортировать файл IO List с учётом двухуровневого заголовка и форматированных разделителей (или задать строку, с которой начинается заголовок).
2. Нормализовать данные: убрать служебные строки, заменить «-» на NULL, развернуть составные поля.
3. Считываемые данные записывать в выбранную БД ACCESS в таблицу **`IO_LIST`** (структура — раздел Б8 `IOclass.md`, 130 колонок) по кнопке; если файла БД нет или таблицы `IO_LIST` нет — создать их. Ключевое поле **`Tag`** (уникальный индекс `UX_IO_LIST_Tag`): если тег уже есть — запись обновляется по правилу идентичности `Tag`+`System`+`Plant` (F2.8), если нет — создаётся новая строка (upsert). Даты внесения и изменения — в `REV_DateEntered` / `REV_DateModified` (проставляются программой).
4. Обеспечить CRUD-доступ из C# (OleDb/ACE).
5. Обеспечить валидацию и трассировку импорта (файл → `REV_FileName`, строка → `REV_RowNumber`, дата → `REV_DateEntered`).

## 2. Область данных (предметная область)

**Справочники** — единый источник: раздел §9 `IOclass.md` (строки; enum не используется): `Location` (Field/DCS/SIS/GDS/ITCC/MMS/MCC/AUX/LCP/PLC), `System` (DCS/SIS/GDS), `ExType` (Ex.d, Ex.i, …); коды I/O Type (TC, HART, DI-VFC, DI-NAMUR, DI-COM, DO-VFC, DO-P, DO-COM, AI-LP, AI-EP, AI-COM, AO, AO-COM + пометки R, (I), S) — допустимые значения `SignalType`; Auxiliary Instrument (P/B/I/D/R) — поле `Auxiliary`.

**Особенности формата (выявленные при анализе):**
1. Между сигналами — строки-разделители, целиком заполненные «-»: **не импортировать**.
2. «-» в ячейке означает отсутствие значения → **NULL** (не строка «-»).
3. Составной код I/O Type: `AIR-EP(3 WIRES)` → нормализовать до `AI-EP`, число проводников — в примечание (одно из `column1…column10` через маппинг).
4. Типы строк: аналоговый сигнал (датчик), цифровой выход (сирена `DOR-P`), интерлок-реле в SIS (`DOR-VFC`).
5. Состав колонок зависит от поставщика файла — целевое соответствие задаётся в окне сопоставления (F2.2).


### F1. Работа с базой данных Access
- **F1.1** Открытие файла `.accdb`/`.mdb` (провайдер ACE/Jet), проводник выбора файла.
- **F1.2** **Выбор таблицы** из списка существующих таблиц открытой базы; по умолчанию — `IO_LIST`; имя таблицы может быть любым.
- **F1.3** **«Создать таблицу с нуля»** — по структуре раздела Б8 `IOclass.md` (130 колонок + уникальный индекс `UX_IO_LIST_Tag`): имя вводится пользователем (по умолчанию `IO_LIST`); при занятом имени — сообщение; после создания таблица автоматически выбирается для записи. Если в открытой базе нет служебных таблиц (`IO_LIST_Audit`, `MappingTemplates`) — они создаются автоматически при первой записи; недостающие колонки существующей таблицы добавляются автоматически (`ALTER TABLE ADD`).
- **F1.4** **Устойчивость к недоступной базе (часть C):** перед использованием базы выполняется быстрая проверка `DbProbe` (пробное соединение + `SELECT 1` в фоновом потоке с **жёстким лимитом 5 с** — ACE OLE DB не принимает ключи таймаута в строке соединения, а свойство `ConnectionTimeout` доступно только на чтение; у команд — `CommandTimeout = 5…30`): (а) **на старте** приложения, если база по умолчанию недоступна (занята эксклюзивно, нет прав, файл отсутствует) — понятное сообщение с причиной и предложение **выбрать другой файл базы** или выйти; (б) в **«Файл → Открыть базу данных...»** — проверка до переключения, при отказе база НЕ переключается, показывается сообщение с технической причиной; (в) ошибка импорта показывается явным окном, а не только текстом отчёта. **Глобальные обработчики** необработанных исключений (`DispatcherUnhandledException` с продолжением работы, `AppDomain.UnhandledException`, `TaskScheduler.UnobservedTaskException`) — приложение больше не закрывается молча без объяснения. Целевой эффект: проверка занятой базы возвращает понятную причину за ≤5 с вместо блокировки UI.

### F2. Импорт из Excel
- **F2.1** Импортировать лист(ы) файла `.xlsx`: **при открытии выбирать вкладку (лист)** и **строку начала чтения** (первая строка — названия столбцов, по умолчанию строка 1); поддержка нескольких файлов.
- **F2.2** **Авто-определение + окно сопоставления «столбцы Excel ↔ колонки выбранной таблицы Access»:** заголовки Excel определяются автоматически, совпадения имён предлагаются автоматически; ручная привязка — кнопка Bind, запись — Apply, сохранение шаблона. **Номера колонок — только подсказка для эталонного файла** (Instrument Range 14–16, System Range 17–19, Alarm & Interlock Setpoint 20–24; колонки 1–13, 25–28 — по уровням H1/H2), а не требование к импорту. Двухуровневый заголовок учитывается при обнаружении. **Обязательное минимальное поле — `Tag`: без привязки `Tag` Apply/импорт блокируется (ошибка в журнале).**
- **F2.3** Правила очистки:
  - строки, где все ячейки = «-», пропускать;
  - «-» → NULL;
  - `AIR-EP(3 WIRES)` → `AI-EP` (+ примечание о проводниках — в одно из `column1…column10`);
  - `Ex.d`/`Ex.i`/… записываются как есть (без конвертации; enum не используется);
  - **шкалы и уставки:** если значение в Excel **не в формате Decimal** — конвертировать (удалить пробелы, заменить запятую на точку, отбросить нечисловые примеси-единицы); не конвертируется — сохранять исходный текст как есть (колонки TEXT) и выдать предупреждение в отчёте.
- **F2.4** Колонка `Logic No.` (`Z-00111/00112/…`) записывается целиком в поле **`Logic`** (`Identification`, `TEXT(255)`); отдельные таблицы логик (`refLogic`/`relSignalLogic`) **не создаются**.
- **F2.5** Трассировка и автозаполнение (программно, не из Excel):
  - `REV_FileName` — имя открытого файла; `REV_Sheet` — имя вкладки (листа)-источника (F2.16);
  - **`REV_RowNumber` — номер строки Excel, в которой находится `Tag`** (присваивается автоматически, маппингом не переопределяется);
  - `REV_DateEntered` / `REV_DateModified` — момент вставки / изменения;
  - `REV_Author` — Windows-логин (`домен\логин`); `Code` = `REV_RowNumber − 1`, если колонка Excel с `Code` не сопоставлена;
  - `PTag_*` — вычисляются из `Tag`;
  - каждое действие фиксируется в `IO_LIST_Audit` (F7).
- **F2.6** Отчёт по импорту: считано строк / импортировано / обновлено / пропущено разделителей / ошибок; ошибки — с номером строки Excel и кодом ошибки; события — в журнал (белый — норма, жёлтый — предупреждение, красный — ошибка).
- **F2.7** Режимы: **«Добавить» = upsert по `Tag`** (по умолчанию; условия обновления — F2.8) и **«Заменить»** (очистить таблицу перед импортом, с предупреждением). **Повтор тега внутри одного Excel-файла не блокирует строку** — строка пишется штатным upsert'ом, а все копии тега копируются в `IO_LIST_DublicateTag` (F2.17; исключение — массовый маркер ≥10 повторов — ошибка `E005`). **Галочка «Импорт с аудитом»** (по умолчанию включена): выключена → записи в `IO_LIST_Audit` не выполняются (включая критические), события журнала окна сохраняются; ручные операции (карточка, удаление) аудируются всегда.
- **F2.8** **Правило идентичности и отсечение неизменённого (`Tag` + `System` + `Plant`):**
  - существующий в БД `Tag` обновляется, только если `System` и `Plant` совпадают с импортируемыми (Trim, без учёта регистра); **пустое входное значение = проверка пропускается** → предупреждение `W003` (конфликт только при явном различии обоих заданных значений);
  - различие → **критическая ошибка**: строка игнорируется, в `IO_LIST_Audit` пишется `CriticalError` (значения БД → Excel), в отчёт — код `E009`;
  - если данные полей **не изменились** → **ни UPDATE, ни записи в аудит** (счётчик «без изменений» в отчёте);
  - если изменились → **частичный `UPDATE` только по изменившимся полям** (+служебные `REV_*`/`PTag_*`) и аудит только по ним;
  - новое поле **`Plant`** входит в `Identification` (структура Б8 — 130 колонок) и участвует в сравнении вместе с `System`.

- **F2.9** **Сессия массовой записи (производительность импорта):** импорт выполняется в **одной сессии БД** — одно соединение + одна транзакция на весь файл (вместо открытия соединения и транзакции на каждую строку); данные фиксируются одним `COMMIT` в конце (`EndSession`), при ошибке — `ROLLBACK` всего импорта (`AbortSession`, идемпотентно). Записи аудита (`IO_LIST_Audit`) в режиме импорта **буферизуются в памяти** (`BeginBatch`) и пишутся одной транзакцией после коммита данных (`EndBatch`); при отмене буфер отбрасывается (`DiscardBatch`) — при ошибке импорта в БД не попадает ни данных, ни аудита. Ручные операции (карточка, удаление, очистка вне импорта) работают вне сессии — по одному соединению. Построчные события журнала и `Info`-сообщения по каждой строке **подавляются** в сессии (сводка — по завершении импорта); прогресс UI обновляется не чаще ~10 раз/с. Целевой эффект: импорт ~1300 строк — секунды вместо минут.

- **F2.10** **Сравнение только по замаппленным колонкам (F2.8):** при upsert частичное обновление (`ComputeDataChanges`) сравнивает **только колонки, привязанные к Excel** (плюс программно заполняемое `Code`); колонка, не имеющая привязки в маппинге импорта, **не считается изменением** и её значение в БД сохраняется (ранее немаппленная колонка читалась как `null` и затирала заполненное поле БД). Ручные операции (карточка, `Update`) сравнивают все поля — точка приходит целиком из формы.

- **F2.11** **Замена документа (новый документ / новая версия файла):**
  - при нажатии **Apply** в режиме «Добавить (upsert)» выводится вопрос **«Импортируется новый документ?»** (`Да` / `Нет` / `Отмена`): `Да` — штатный импорт (поведение без изменений); `Отмена` — импорт не выполняется;
  - при `Нет` открывается диалог **«Взамен какого документа?»** со списком документов целевой таблицы (**пары «файл + вкладка»**: `SELECT DISTINCT REV_FileName, REV_Sheet`, непустые файлы; отображение «файл :: вкладка», старые записи без вкладки — «файл (без вкладки)»); пустой список → предупреждение, замена невозможна; отмена диалога → импорт не выполняется;
  - импорт выполняется с параметрами `ImportOptions.ReplacedFileName` + `ImportOptions.ReplacedSheet` (файл и вкладка заменяемого документа):
    - **новые/переименованные теги** (нет в БД) — вставка штатным upsert (изменение `Tagname` = старый тег помечается, новый добавляется);
    - **теги заменяемого документа, присутствующие в новом файле** — обновляются upsert'ом, их `REV_FileName` и `REV_Sheet` переносятся на новый документ (аудит `Update` по `REV_FileName`, а при смене вкладки — дополнительно по `REV_Sheet`; линовка версий документа сохраняется);
    - **теги заменяемого документа, отсутствующие в новом файле** — **пометка без физического удаления**: `REV_Description` = «Удаляются, отсутствуют в последней версии файла <имя нового файла>», `REV_DateModified` = now; в `IO_LIST_Audit` пишется действие **`MarkedDelete`** (поле `REV_Description`, старое → новое), в отчёт — предупреждение **`W004`** и счётчик «помечено к удалению»; строки **остаются в БД** — физическое удаление выполняет пользователь после проверки;
    - сравнение ведётся **только по строкам выбранного документа — пары «`REV_FileName` + `REV_Sheet`»** (F2.16); строки других документов **и другие вкладки того же файла** не затрагиваются; документ без вкладки (старые записи, `REV_Sheet` IS NULL) матчится только с позицией «без вкладки»;
    - **красная индикация:** записи `MarkedDelete` отображаются красным в окне истории (F7.5) и при выгрузке аудита в Excel (красный шрифт), в журнале событий — красными строками «помечен к удалению (необходимо удалить из БД)»;
  - режим «Заменить (очистить)» и вопрос/диалог не используются (таблица очищается целиком);
  - повторный импорт того же файла как замена самому себе (`ReplacedFileName` = имя нового файла **и та же вкладка** `ReplacedSheet`) — служебный перенос `REV_FileName`/`REV_Sheet` не выполняется (идемпотентность), пометка отсутствующих тегов — выполняется.

- **F2.12** **Зачёркнутые строки Excel (правило отсечения):** строка, в которой ячейка **`Tag` зачёркнута** (шрифт с зачёркиванием в ячейке Excel), **исключена из проекта**: не импортируется, **не попадает в БД**, её тег **не регистрируется** среди обработанных (`seenTags`) — при замене документа (F2.11) такой тег помечается как отсутствующий в новой версии. В отчёт — предупреждение **`W005`** + счётчик «зачёркнутых пропущено», в журнал — предупреждение по каждой строке (номер строки + текст тега) и итоговый перечень зачёркнутых тегов. Если зачёркнута **другая ячейка** (не `Tag`) — её значение считается **пустым (`NULL`)**, как при «-» (F2.3). Зачёркнутые строки и ячейки **подсвечены зачёркиванием в предпросмотре** окна импорта (тултип «строка не будет импортирована» / «значение не будет импортировано»). Гарантия журнала (Задание п.8): **каждая критическая ошибка валидации** (`E002`/`E004`/`E005`/`E009`, а также `E003` — иерархия уставок, не блокирующая запись) пишется в журнал событий **немедленно и всегда** — журнал не зависит от галочки «Импорт с аудитом» (при выключенном аудите данные в `IO_LIST_Audit` не пишутся, но все красные события журнала сохраняются).

- **F2.13** **Пустая ячейка шапки → строка выше:** если ячейка строки заголовка (`HeaderRow`) пуста, имя колонки читается из ячейки `(HeaderRow − 1)` той же колонки (двухуровневый заголовок эталонного файла); при `HeaderRow = 1` fallback не применяется. Пустое имя после fallback остаётся пустым — колонка без имени в маппинг не попадает.
- **F2.14** **Дубликаты заголовков Excel → разные колонки таблицы:** каждая привязка несёт 0-based позицию колонки `ColumnMap.ExcelColumnIndex` (в шаблонах — тоже; старые шаблоны без индекса резолвятся по имени). Отображение в окне маппинга — **«MIN (столбец H)»**. `AutoDetect` проставляет индексы всем строкам и подсказку о дубликате (`заголовок встречается N раз — колонка определяется позицией`): первое вхождение имени получает авто-привязку, повторные — нет (E008-страховка). При импорте/в предпросмотре колонка резолвится по позиции (совпадает ли в этой колонке ожидаемое имя), иначе — по имени. Уникальность колонок таблицы (E008, привязка 1:1) сохраняется.
- **F2.15** **Очистка `Tag` от пробелов:** из значения `Tag` удаляются **все** пробельные символы (включая NBSP `\u00A0`) — в импорте (до `PTag_*`-автозаполнения, валидации и upsert) и в карточке (до проверки обязательности). Изменение фиксируется: предупреждение **`W006`** в отчёте/журнале + действие **`TagCleaned`** в `IO_LIST_Audit` (старое → новое значение, отображается **красным** в окне истории и при выгрузке) с контекстом «файл + вкладка + система». При выключенной галочке «Импорт с аудитом» запись `TagCleaned` не выполняется (как весь аудит импорта).
- **F2.16** **Документ = файл + вкладка:** идентификация документа в БД — пара `REV_FileName` + `REV_Sheet` (имя вкладки-источника; колонка добавлена в дерево, тип `TEXT(255)`, автозаполнение как `REV_FileName`; существующие таблицы мигрируются `ALTER TABLE ADD` через `EnsureColumns`). Разные вкладки одного файла — **разные документы**: сигналы вкладок разделяются, замена документа (F2.11) работает строго в пределах выбранной пары, строки других вкладок не затрагиваются. Идентичность `Tag`+`System`+`Plant` (F2.8) и уникальность `UX_..._Tag` не меняются: один тег — одна запись, `REV_Sheet` обновляется при импорте/переносе документа. `REV_Sheet` входит в авто-колонки (маппингом не переопределяется) и в контекст аудита (F7.7).

- **F2.17** **Итерация: дубликаты тегов и замена нескольких документов.** Две части:
  - **(а) Повторы тегов → `IO_LIST_DublicateTag` (дубликаты).** Перед записью считается частота тегов в файле (нормализация как в F2.15). Обычный повтор (тег встречается 2…9 раз): строка **не пропускается** — пишется штатным upsert'ом (первая копия вставляет, повторные обновляют — уникальный индекс `UX_IO_LIST_Tag` сохраняется), а **все строки с повторяющимся тегом (включая первую)** дополнительно копируются в таблицу **`IO_LIST_DublicateTag`** — структура = `IO_LIST` (`Schema.CreateTable`, 130 колонок), **без уникального индекса** `UX_..._Tag`; таблица создаётся автоматически перед импортом (`EnsureDuplicateTagTable`, идемпотентно), мигрирует `ALTER TABLE ADD`; аудит копий не пишется. В отчёт — предупреждение **`W007`** (одно на тег) и счётчик «копий в IO_LIST_DublicateTag»; строки с конфликтом `E009` копию не получают. **Массовый маркер:** тег, повторяющийся в файле **≥10 раз**, считается служебной заглушкой — строка не записывается ни в `IO_LIST`, ни в копии (ошибка **`E005`**, счётчик «массовых маркеров пропущено»); пустые теги (`E002`) — не записываются (F5.1).
  - **(б) Мультивыбор документов при замене (F2.11/F2.16).** Диалог «Взамен каких документов?» — список с **множественным выбором** (`SelectionMode=Extended`, Ctrl/Shift) + кнопки «Выбрать все»/«Снять всё» + счётчик выбранных; документы делятся по ревизиям/вкладкам. `ImportOptions.ReplacedDocuments` — список пар «файл + вкладка» (одиночная замена — частный случай). `MarkMissingTagsForDeletion` работает со **всеми выбранными парами** одним параметризованным `WHERE ... OR ...`: отсутствующие в новом файле теги каждого документа помечаются (`MarkedDelete`, `W004`, маркер идемпотентен); выжившие переносятся на новый документ, причём **`OldValue` аудита `Update REV_FileName` = реальный прежний документ записи** (в мульти-замене записи приходят из разных документов); запись, уже принадлежащая новому документу, не переносится (повторный импорт идемпотентен). Выбор только нового документа = повторный импорт (пометки выполняются, перенос — нет).

### F5. Валидация данных
- **F5.1** Обязательность и минимальная длина `Tag`; наличие привязки `Tag` в маппинге (без неё импорт блокируется — F2.2).
- **F5.2** Иерархия тревог: `LL2 ≤ LL ≤ L ≤ H ≤ HH ≤ HH2` — проверяется **после конвертации** значений в число (F2.3); единицы измерения не хранятся и не проверяются; неконвертируемое значение — предупреждение (значение сохранено как есть, TEXT). Нарушение иерархии (`E003`) — **не блокирует запись**: строка импортируется в БД (в т.ч. из-за «0 = уставка не задана» в SIS-файлах), сообщение попадает в отчёт/список ошибок с пометкой «строка будет записана».
- **F5.3** Диапазоны: `Range_MIN < Range_MAX` и `Range_MIN2 < Range_MAX2` — после конвертации (F2.3); иначе ошибка `E004` — строка **не записывается**.
- **F5.4** Ссылочная целостность: `Location`/`System`/`ExType`/`IoType`/`Auxiliary` — допустимые значения справочников §9 `IOclass.md` (хранение строками).
- **F5.5** Результат валидации — список ошибок/предупреждений с указанием `Tag` и имени поля (структура `ValidationResult` — в разделе §6).

### F7. История изменений и выгрузка в Excel
- **F7.1** Каждое **добавление** и **изменение каждого поля** фиксируется в служебной таблице той же базы **`IO_LIST_Audit`**:

| Колонка | Тип | Описание |
|---|---|---|
| `ID` | COUNTER PK | автономер записи истории |
| `TableName` | TEXT(255) | имя затронутой таблицы (напр. `IO_LIST`) |
| `Tag` | TEXT(255) | тег записи |
| `ChangeAction` | TEXT(50) | `INSERT` / `UPDATE` / `DELETE` / `CriticalError` / `MarkedDelete` / `TagCleaned` (имя `Action` — зарезервировано Access) |
| `FieldName` | TEXT(255) | имя колонки |
| `OldValue` | TEXT(255) | старое значение (NULL при INSERT) |
| `NewValue` | TEXT(255) | новое значение (NULL при DELETE) |
| `REV_FileName` | TEXT(255) | **F7.6:** документ-источник изменения (из какого Excel-файла инициировано; NULL для старых/ручных записей) |
| `REV_Sheet` | TEXT(255) | **F7.7:** вкладка-источник изменения (документ = файл + вкладка, F2.16; NULL для старых/ручных записей) |
| `System` | TEXT(255) | **F7.6:** система изменения — произвольное значение записи (`DCS`/`SIS`/`GDS`/`РСУ`/`ПСБ`/…) |
| `ChangedBy` | TEXT(255) | Windows-логин (`домен\логин`) |
| `ChangedAt` | DATETIME | момент изменения (системные часы) |

```sql
CREATE TABLE IO_LIST_Audit (
  ID COUNTER PRIMARY KEY,
  TableName TEXT(255), Tag TEXT(255), ChangeAction TEXT(50),
  FieldName TEXT(255), OldValue TEXT(255), NewValue TEXT(255),
  REV_FileName TEXT(255), REV_Sheet TEXT(255), System TEXT(255),
  ChangedBy TEXT(255), ChangedAt DATETIME
);
```

> Существующие таблицы аудита **мигирируются автоматически**: при отсутствии `REV_FileName`/`REV_Sheet`/`System` выполняется `ALTER TABLE [IO_LIST_Audit] ADD COLUMN … TEXT(255)` (`ServiceSchema.EnsureServiceTables` через `Schema.AuditContextColumns`, идемпотентно); старые записи получают NULL.

- **F7.2** Формат: «что на что менялось» — одна строка на изменённое поле; добавление записи — строки по всем заполненным полям (`ChangeAction=INSERT`, `OldValue`=NULL); удаление — `ChangeAction=DELETE`, `NewValue`=NULL.
- **F7.3** **Экспорт истории в Excel** (`.xlsx`): фильтры по `Tag`, дате, полю, действию, **документу (`REV_FileName`)**, **вкладке (`REV_Sheet`, F7.7)** и **системе (F7.6)**; кнопка «Выгрузить в Excel» в окне истории; в выгрузку включены колонки «Файл (REV_FileName)», «Вкладка (REV_Sheet)» и «Система».
- **F7.4** История только читается из UI (редактирование и удаление строк истории запрещены); экспортируются также текущие данные репозитория (отчёт по п. F6.1).
- **F7.5** Записи `CriticalError` (конфликт идентичности System/Plant, F2.8), `MarkedDelete` (пометка на удаление при замене документа, F2.11) и `TagCleaned` (очистка `Tag` от пробелов, F2.15) отображаются в окне истории красным; при выключенной галочке «Импорт с аудитом» записи истории на время импорта не выполняются.
- **F7.6** **Контекст изменения (документ + система):** каждая запись аудита несёт `REV_FileName` (инициирующий документ: имя импортируемого файла; для `MarkedDelete`/переноса выживших — **новый** файл) и `System` (система затронутой/импортируемой записи). Источники: `IoPoint.Revision.FileName` / `IoPoint.Identification.System` при импорте и ручных операциях; для `MarkMissingTagsForDeletion` — `System` читается из БД. Окно истории: **колонки «Файл» и «Система»** + **фильтры по ним** (подстрока, `LIKE`); в `GetHistory` — параметры `fileName`/`system`. Для записей без известного контекста (`Clear`, старые записи) — NULL.
- **F7.7** **Контекст вкладки (файл + вкладка = документ):** каждая запись аудита дополнительно несёт `REV_Sheet` — имя вкладки-источника (`options.SheetName` / `IoPoint.Revision.Sheet`); для `MarkMissingTagsForDeletion` — новая вкладка документа. Окно истории: **колонка «Вкладка»** + **фильтр по ней** (подстрока, `LIKE`); в `GetHistory` — параметр `sheet`; в выгрузке Excel — колонка «Вкладка (REV_Sheet)». Существующие таблицы аудита мигрируются автоматически (`Schema.AuditContextColumns` += `REV_Sheet`, ALTER TABLE ADD); старые записи — NULL. Связка с F2.16: одна и та же запись истории всегда указывает на ту же пару «файл + вкладка», что и данные `IO_LIST`.
- **F7.8** **Формирование отчёта (сводка по документам):** кнопка «Формирование отчёта...» в окне истории (рядом с «Выгрузить в Excel...») открывает окно отчёта. Данные — SQL-агрегат `AuditService.GetSummary`: `SELECT REV_FileName, REV_Sheet, FieldName, ChangeAction, COUNT(*) … GROUP BY …` (**те же фильтры**, что в окне истории; считается вся таблица аудита, а не только отображаемые 500 записей `GetHistory`). Построение строк — `ReportBuilder.Build`: для каждого документа «файл :: вкладка» — по каждой ячейке (полю) счётчики по типам изменений (`Insert`/`Update`/`Delete`/`CriticalError`/`MarkedDelete`/`TagCleaned`/`Duplicate`) и «Всего» (напр. `Service: 56`), строки сортируются по убыванию «Всего», затем — полужирная строка-итог документа «ИТОГО» и общая строка «ВСЕГО»; внизу окна — «Документов: N · Всего изменений: M», в шапке — условие отбора (текущие фильтры). Документы с NULL: «(без файла)», «(без вкладки)». Выгрузка — `ExcelExportService.ExportAuditReport` (лист «Отчёт»: заголовок + условие отбора, таблица с теми же колонками, итоги — полужирным с заливкой). Открытие окна — через хук `HistoryViewModel.OpenReport` (MVVM, VM не ссылается на Views).

### F9. Карта адресации Modbus (M_-поля, MODBUS_MAP, связывание)

- **F9.0** **Схема M_-полей (29 колонок):** в `IO_LIST` перед `CBL_Id` добавлен блок колонок `M_*` (все TEXT(255)): `M_MapFile`, `M_SlaveStation`, `M_SlaveIdMain`, `M_SlaveIdBackup`, `M_Speed`, `M_Timeout` (Interface parameters), `M_PrfDesignation`, `M_PlcTag`, `M_ObjectTag`, `M_Description`, `M_Units`, `M_Scale`, `M_LL`, `M_LA`, `M_HA`, `M_HH`, `M_Scaling`, `M_SigType`, `M_RegType`, `M_Address`, `M_AccessType`, `M_DataType`, `M_FuncCode`, `M_DcsChannel`, `M_DcsTag`, `M_DcsFunctions`, `M_Note` (Register Table), `M_BusBlock`, `M_BusDataOut` (F13: привязки блоков Modbus SCADA — имя блока и путь `Block.DataOut[i]`, заполняются кнопкой окна F13). Итого `IO_LIST` — 130 колонок (+ID; F14: +`Typno` — типовой алгоритм в Identification, 129→130). Модель — группа `IoPoint.Modbus` (`Models/ModbusMapEntry`-семейство), реестр — `FieldRegistry`, описания — `FieldDescriptions`. Существующие таблицы мигрируются автоматически (`EnsureColumns`, ALTER TABLE ADD). Карточка точки показывает M_-поля как обычные колонки.
- **F9.1** **Задвоение тега между документами (равноправный аудит):** при upsert, если тег уже существует в БД **из другого документа** (файл + вкладка ≠ текущему) и исход — `Updated`/`Unchanged`, в `IO_LIST_Audit` пишется равноправная запись **`Duplicate`** (поле `Tag`; `OldValue` = прежний документ «файл :: вкладка», `NewValue` = текущий; контекст — инициирующий документ). Замена документов (F2.11/F2.16, список `ReplacedDocuments`) — штатное перенесение, задвоением не считается. Один тег — одна запись Duplicate за сессию импорта. Предупреждение `W008`, счётчик «задвоений между документами» в отчёте импорта; в окне истории и выгрузке Excel записи `Duplicate` — **жёлтым**; в отчёте F7.8 — колонка `Duplicate`.
- **F9.2** **Импорт карты (окно «Импорт → Карта Modbus...»):** разбор файлов «IMCS TO DCS Register Table Modbus» (ClosedXML): лист `Interface parameters` (станция, IP main/backup, скорость, таймаут) + листы `Register Table Function 02/03/06` (шапка — строка 2, данные со строки 3, колонки A..U; `ObjectTag` = PLC Tag до первого «_»). Результат — таблица **`MODBUS_MAP`** (структура — Б8 `IOclass.md`): повторный импорт того же файла заменяет его строки (идемпотентно), строки без привязки хранятся (`LinkTag` пуст). Колонка **`LinkState`** («привязано»/«не привязано»/null) заполняется связыванием F9.3: перед каждым прогоном `LinkTag`/`LinkState` сбрасываются, после прогона строки без результата помечаются «не привязано»; существующие `MODBUS_MAP` мигрируют через `ALTER TABLE ADD` (`EnsureServiceTables`). `MODBUS_MAP` не отображается в списке таблиц главного окна (сетка читает колонки `FieldRegistry`) — просмотр в Access.
- **F9.3** **Связывание (`ModbusLinkService`):** для каждой записи текущей таблицы извлекается кандидат-объект ПЛК: (1) ссылка в скобках Service/ServiceEnglish «(1110-KM-101A-1)» — приоритет 1; (2) ведущее обозначение Service/ServiceEnglish «1115-P-101A» (оба поля сканируются, дубли скобочных ссылок отбрасываются; ASCII-границы — тег, приклеенный к кириллице «1115-P-101AСостояние», распознаётся) с нормализацией P→PM, K→KM и уборкой ведущих нулей — приоритет 2; (3) `Loop` с подстановкой классов PM/KM — приоритет 3. Роль сигнала → строка карты: команда (`DO-COM` / «command:») → Function 06 (Control word, PlcTag = объект без суффикса; MCC-команды делят один регистр, все их теги перечисляются в `LinkTag` через запятую); статусы (`fault`/`running`/`ready`/`communication`/`permitted`/`emergency`/`switch`/`mccb`) → Function 02 с суффиксом `FAULT.MCU`/`STA.MCU`/`REDAY.MCU`/`TX.MCU`/`PERMIT.MCU`/`EM_STOP.MCU`/`SWITCH_ON.MCU`/`MCCB POSITION.MCU`; ток (`AI-COM` / «current») → Function 03 `I_A`. Сопоставление — пять уровней, на каждом сначала стандартный суффикс, затем уровень «по описанию»: (1) точный `ObjectTag` → (2) префикс («.XX») → (3) базовое устройство (срез «-N»/«.XX», классы карты нормализуются P→PM/K→KM — «насос 1120-P-203A.HE-JB = двигатель 1120-PM-203A»), внутри каждого уровня: точное совпадение `PlcTag` → `EndsWith("_суффикс")` → (4) **по ключевым словам роли в `Description` строки карты** с фильтром FuncCode (уровень «карта со своими суффиксами»: `_Q3_F.PLC`/`_Q3_READY.PLC`/`_Q3_BYPS.PLC`/`_M3_PERMIT.PLC`/`_FAULT.PLC`/`_REDAY.PLC` и т.п. — описания карты и Service IO используют один словарь: fault/Ready/Running/Permit/Communication/Emergency); позиция автомата `_QF?_STA.PLC` («Switch Closing») под running не попадает — по описанию; неоднозначность (объекты `2701-PK-1201A/B-M`: `_TX.VFD` + `_TX.PLC` — оба «Communication») решается первым совпадением в порядке строк карты. При совпадении заполняются `LinkTag`/`LinkState`/`DcsTag` строки карты (F9.4: M_-поля в `IO_LIST` при импорте **не** записываются — адресацию заполняет кнопка «Обновить адресацию Modbus»); связь допустима только для Modbus-сигнала (IO Type: первая буква `M` либо содержит `COM`), для не-Modbus-сигнала связь не записывается и формируется ошибка. После прогона строки без результата получают `LinkState` = «не привязано» (итоги — «карта: привязано X, без привязки Y», в превью окна — до 10 PlcTag без привязки). **Устойчивость к блокировкам (F9-фикс):** привязки копятся в памяти и записываются после цикла одной транзакцией (`ApplyLinkResults`: привязки + `DcsTag` + разметка остальных «не привязано» атомарно) — открытая сессия по `IO_LIST` в связывании больше не используется, что устраняет ошибку JET 3260 «Could not update; currently locked»; операции записи карты (`SaveToDb`, сброс/запись привязок) при кратковременной блокировке повторяются до 3 раз (пауза 300/600 мс); имя упавшего файла карты и человекочитаемая причина (`DbProbe.ClassifyMessage`) показываются в окне импорта. Несопоставимые записи IO — в превью окна с причинами. Итог: проверено/связано/строк карты/не связано/карта (+ ошибки связывания); M_-поля не записаны — их заполняет кнопка «Обновить адресацию Modbus» (F9.4).

- **F9.4** **Кнопка «Обновить адресацию Modbus» (запись M_-полей, `ModbusLinkService.UpdateAddressing`):** отдельная команда главного окна — пункт меню «Импорт → Обновить адресацию Modbus» и кнопка тулбара «📡 Modbus адресация» (в окно импорта карты не встроена). Для всех строк `MODBUS_MAP` с непустым **`DcsTag`** (ключ связи `MODBUS_MAP.DcsTag ↔ IO_LIST.Tag`; список тегов через запятую — как в `LinkTag`) находится точка `IO_LIST` по `Tag` и в одной сессии (транзакция + батч аудита F2.9/F7) заполняются все `M_*`-поля (`FillModbus` + `Update` — аудит `Update` по каждому изменённому полю, равноправно F7). **Фильтр Modbus-сигналов:** обновляются только точки с признаком Modbus в `IO Type` (`ModbusLinkService.IsModbusSignal`: первая буква `M`, напр. `MAI`, либо содержит `COM`, напр. `AI-COM`); если пара найдена, но точка — не Modbus-сигнал, формируется ошибка «в карте адресации modbus указан DCSTAG не Modbus сигнала: «тег» (IO Type «X» — нет признака M*/COM)», `M_*` не заполняются. Тег из `DcsTag`, отсутствующий в `IO_LIST` — счётчик «не найдено» + примеры (≤10). Повторное нажатие идемпотентно (без изменений `Update` возвращает 0). Итог (счётчики + ошибки ≤10 + не найденные) показывается в MessageBox и в инфо-строке; блокировки — `TakeLockWarning`, ошибки — `DbProbe.ClassifyMessage`. **Заполнение `DcsTag` при импорте (эвристика F9.3):** в колонку `S`/`DcsTag` строки карты дописывается `Tag` связанной точки накопительно через запятую (ручной ввод в Access не затирается, дубли не добавляются); `ResetLinkResults` `DcsTag` не сбрасывает. `MODBUS_MAP.DcsTag` читается из колонки S файла карты (в исходниках пуст).

- **F9.5** **Drag&drop окна импорта карты:** в `ModbusImportWindow` перетаскивание файлов `*.xlsx` работает как кнопка «Добавить файлы...» — все файлы из списка добавляются в `Files` (дедуп, фильтр расширения; `ModbusImportViewModel.AddFiles(IEnumerable<string>)`); подтверждение перетаскивания — `DragDropEffects.Copy` только для Excel-файлов (по образцу окна импорта Excel `ImportWindow`).

- **F9.6** **Гибкое сопоставление классов (`ModbusLinkService.ClassVariants`):** карта и IO_LIST часто пишут класс привода по-разному (`1162-M-401` против `1162-PM-401`). При поиске строки карты для кандидата класс перебирается тремя шагами, точное написание приоритетнее: (1) точное; (2) таблица эквивалентов `{PM↔M, EM↔E, AGM↔AG, BLM↔BL}` (обе стороны; `BLM↔BL` — F9.10: вентиляторы охлаждающей башни `2622-BLM-101A` в карте против `2622-BL-101A` в IO_LIST); (3) итеративное удаление букв класса (BFS по уровням удалений: сначала `M` — наиболее вероятная разница карты, затем по одной букве слева направо; класс не может стать пустым — должна остаться минимум 1 буква). Титул и числовой номер (включая хвосты `-N`/`_суффикс`/`.XX`) сохраняются строго. Перебор применяется на всех трёх уровнях поиска (точный `ObjectTag` → префикс «.XX» → базовое устройство); точные совпадения всех вариантов приоритетнее префиксных.

- **F9.7** **Канонизация тегов — ведущие нули (`ModbusLinkService.CanonTag`):** дефект «кандидат `1120-PM-3A` ≠ ключ карты `1120-PM-003A`» устранён: ключи индекса карты (`ObjectTag`) и все сравнения `PlcTag`/`ObjectTag` выполняются в канонизированном виде — ведущие нули числовой номера срезаются с обеих сторон (`003A` ↔ `3A`; в том числе в PlcTag с суффиксом: `00003A_TX.PLC` ↔ `3A_TX.PLC`); титул/класс/хвост не меняются. `BaseDevice` (базовое устройство) также возвращает канонический вид.

- **F9.8** **Сообщения связывания в аудите (`IO_LIST_Audit`):** сообщения связывания/адресации попадают не только в журнал, но и в историю изменений. Предупреждения «Не связано: …» (≤20 — тот же набор, что в журнале) и «тег из DcsTag не найден в IO_LIST» — действие **`ModbusWarning`** (жёлтый); ошибки «связь отклонена … не Modbus-сигнал» и «в карте адресации modbus указан DCSTAG не Modbus сигнала» — действие **`ModbusError`** (красный). Содержимое записи: поле `Modbus`, `NewValue` = текст сообщения (как в журнале), `System` = «Modbus», документ-контекст — `REV_FileName`/`REV_Sheet` точки (для сообщений адресации — `MapFile`/`MapSheet` строки карты-источника). Запись выполняется **после** закрытия транзакции/сессии (`ApplyLinkResults`/`EndSession`); сбой записи аудита не прерывает связывание (только предупреждение в журнал). Записи видны в окне истории и выгрузке Excel (предупреждения — жёлтым, ошибки — красным) и учитываются в отчёте F7.8 (колонки `ModbusWarning`/`ModbusError`). Аудит append-only: повторные прогоны добавляют новые записи со своим `ChangedAt`.

- **F9.9** **Кнопка «Обновить связи Modbus (DcsTag)» + глобальный переключатель аудита:**
  - **Кнопка** (меню «Импорт → Обновить связи Modbus (DcsTag)» + тулбар «🔗 Modbus связи») запускает `ModbusLinkService.Link()` по **уже сохранённой** карте `MODBUS_MAP` — без импорта файлов. Предназначена для случая ручных правок/добавления сигналов в Access: пересчитываются `LinkTag`/`DcsTag`/`LinkState` строк карты по кандидатам Service/Loop. Итог — MessageBox (проверено/связано/не связано + примеры «Не связано»/«Карта без привязки» ≤10 и ошибки ≤10); при пустой `MODBUS_MAP` — подсказка сначала импортировать карту. `M_*`-поля не записываются — их пишет «Обновить адресацию Modbus» (F9.4).
  - **Чекбокс «Вести аудит (IO_LIST_Audit)»** в окне импорта карты Modbus управляет **глобальным** флагом `AuditService.Enabled` (по умолчанию включён; действует на все операции текущего сеанса — импорт Excel, редактирование, связывание, адресацию).
  - **При выключенном аудите** записи в `IO_LIST_Audit` не выполняются; в **журнале событий** остаётся минимизация: единичные изменения — «Аудит выключен: изменён тег «X» — в историю не записано» (только имя `Tag`, без значений полей); пакетные (импорт, сессии репозитория) — одна сводная строка «Аудит выключен: изменения в N тег(ах) не записаны в историю: …» со списком уникальных тегов (≤20 + «…»); сообщения связывания F9.8 продолжают попадать в журнал, как и при включённом аудите (в историю — нет).
- **F9.10** **Новые роли связывания VFD/скорость/run (2026-10):** `DetectRole` дополнительно распознаёт: (1) **run-сигнал** — Service «… run signal»/«Run» (2000 MCC) наравне с «running» → суффикс `STA.MCU` — раньше такие записи уходили в «Не связано»; (2) **задание скорости** — `MSC` (IO Type `AO-COM` / «speed control» / тег `…-MSC-…`) → роль `FREQ_SET` → строка Function 06 «Frequency Setting» (по ключевым словам Description с фильтром FuncCode — **один** сигнал на регистр); (3) **считывание скорости** — `MSI` («speed signal» / тег `…-MSI-…`) → роль `SPEED` → Function 03 «Operating Frequency» (`_OP_F`); ветка MSI проверяется **раньше** общей ветки тока `AI-COM → I_A`, иначе MSI ошибочно привязывался к «Output Current»; (4) **роль по суффиксу тега DCS**, если Service не распознан ключевыми словами: `MXA…A` → `FAULT.MCU`, `MXA…B` → `STA.MCU`, `MXA…C` → `REDAY.MCU`, `MII` → `I_A`, `MHS` → команда (Control word), `MSC`/`MSI` → скорость. **Выбор Function 06 для команд:** если у объекта несколько строк Function 06 (VFD: «Frequency Setting» + «Control word … Value:1=Stop,…»), команда (`DO-COM`) привязывается к строке с «Control word»/«Value:1=Stop» — все MHS-команды объекта (stop/start/permissive/ban) делят один регистр через запятую в `LinkTag`, а «Frequency Setting» достаётся только `MSC`. Эквивалент классов F9.6 пополнен парой `BLM↔BL` (вентиляторы охлаждающей башни: карта `2622-BLM-101A` ↔ IO_LIST `2622-BL-101A`). Смоук — 113 проверок (F9.10: 17, в т.ч. регрессия на реальных файлах OBSL2203/OBSL3404 + 2000 MCC).
  - **F9.11** **Ручные правила связывания (`MODBUS_LINK_RULES`, 2026-10):** таблица правил в Access дополняет встроенные эвристики связывания пользовательскими зависимостями «поле IO_LIST ↔ поле `MODBUS_MAP`». Структура: `Name`, `IOField` (`Tag`/`Service`/`ServiceEnglish`/`IoType`/`Loop`/`SignalType`), `TagPattern`, `MapField` (любое строковое поле `ModbusMapEntry`: `Description`, `Scale`, `PlcTag`, `FuncCode`, …), `ValuePattern`, `FuncCode` (опциональный фильтр «02»/«03»/«06»), `Priority` (меньше — раньше), `Enabled`. **Семантика шаблонов** (`TagPattern`/`ValuePattern`, `IgnoreCase`): (1) начинается с `*`/`?` либо содержит только wildcard-метки → wildcard (анкорный: `*` — любые символы, `?` — один; пример `*Fault*`); (2) содержит метасимволы regex (`. + ^ $ ( ) [ ] { } | \`) → регулярное выражение (примеры `MXA.*A`, `MXA+A`); невалидный шаблон → правило пропускается с предупреждением в журнале (связывание не падает). **Приоритет:** в `Link()` ручные правила применяются **ПЕРЕД** встроенными ролями `DetectRole` (первое сработавшее правило по `Priority` выигрывает; если ни одно правило не сработало — обычная логика ролей). Поиск строки карты идёт тремя уровнями как в `FindMapRow` (точный `ObjectTag` → префикс «.XX» → базовое устройство, с `ClassVariants`/`CanonTag`) с фильтром `MapField LIKE ValuePattern` (+`FuncCode`); ограничение F9.4 сохраняется — связь только для Modbus-сигналов. Статистика: `ModbusLinkResult.LinkedByRule`/`RuleHits` (имя правила → число тегов) + сообщение в журнале; итог саммари дополняется «правилом F9.11: N». **Редактирование:** меню «Импорт → Правила связывания Modbus...» → окно с `DataGrid` (Вкл/Название/Поле IO/Шаблон тега/Поле карты/Шаблон значения/FuncCode/Приоритет), кнопки «Добавить/Удалить/Проверить/Сохранить»; сохранение — валидация всех правил (`ModbusLinkRuleService.Validate`: имя, поля IO/карты, шаблоны) и полная замена строки таблицы (`DELETE`+`INSERT` одной транзакцией, повтор при блокировке). Таблица создаётся идемпотентно в `TableCreator.EnsureServiceTables` (существующие базы получают её при открытии/записи служебных таблиц). Хранилище — `ModbusLinkRuleService` (`Load`/`LoadEnabled`/`SaveAll`, `PatternMatch`/`Compile`/`Validate`); `ModbusLinkService` принимает его через конструктор (`AppServices.ModbusLinkRules`). Смоук — 138 проверок (F9.11: 25).
- **F12** **Генерация перечня Modbus (Тех.объекты) для SCADA (2026-10):** меню **«SCADA → Генерация перечня Modbus (Тех.объекты)...»** формирует файл перечня технологических объектов для импорта в SCADA по образцу `Work\ТехОбъекты_простой.xls` (спецификация — `Генерация технологических объектов Modbus.md`). **Источник строк:** текущая таблица, только точки с заполненной адресацией Modbus (`M_PlcTag`, записывается «Обновить адресацию Modbus» F9.4); ## 5. Нефункциональные требования

- **N1. Платформа:** Windows 10/11 x64; .NET 8 (WPF); Microsoft Access Database Engine (ACE OLE DB 12.0) установлен на целевой машине.
- **N2. Производительность:** импорт файла ~1000 строк — до 10 с; поиск по списку ≤ 1 с; чтение всех записей ≤ 2 с на 10 000 строк.
- **N3. Целостность:** транзакционность импорта одной таблицы (весь файл — одной транзакцией либо откат при ошибке); уникальный индекс `UX_IO_LIST_Tag`.
- **N4. Надёжность:** перехват исключений OleDb с понятными сообщениями на русском; приложение не падает при ошибке БД/файла (лог + диалог).
- **N5. Локализация:** интерфейс и журнал — русский; данные — как в источнике (EN).
- **N6. Безопасность:** параметризованные запросы (защита от SQL-инъекций); экранирование спецсимволов LIKE; БД открывается только на чтение/запись приложением (без встроенного пароля).
- **N7. Актуальность кода:** код предыдущих итераций (`GdsSignal`, набор IOPointManager) **не актуален** (решение п.3.4) — разработка ведётся заново по `IOclass.md`; существующий каркас `IO_PJT` (WinForms) переиспользуется как референс, но ПО создаётся в WPF.

## 7. Критерии приёмки

1. Проект собирается: `dotnet build` — 0 ошибок.
2. Таблица `IO_LIST` создаётся в Access по DDL из раздела Б8 `IOclass.md` без ошибок; валидация справочников §9 проходит.
3. Импорт эталонного файла `_Specification\пример данных.xlsx` (лист `OSBL_IO_List_SCS_v4`; дополнительно — `D4 NKNH21002-1702-ATX.LST-0005_1_EN.xlsx` как второй профиль):
   - количество импортированных сигналов = числу строк-данных листа (без разделителей);
   - тег `2701-XZY-10101A` присутствует: `System`=SIS, `SignalType`=DOR-P, `ExType`=Ex.d, `Logic`=2701-Z-10001/2701-Z-10004/2701-Z-10101;
   - для аналогового сигнала (тестовые данные): уставки `H`=10, `HH`=20 записаны в колонки `H`/`HH` (единицы измерения не хранятся);
   - `REV_RowNumber`, `REV_FileName`, `REV_DateEntered` заполнены.
4. `GetByTagAsync`, `SearchAsync`, `GetBySystemAsync` возвращают корректные данные.
5. Повторный импорт в режиме «Заменить» не создаёт дублей; режим «Добавить» обновляет существующий тег (upsert) и вставляет новый; повтор тега внутри одного файла — строка записывается, копии попадают в `IO_LIST_DublicateTag` (F2.17), массовый маркер (≥10 повторов) — ошибка `E005`.
6. Ошибки валидации (нарушение `LL2 ≤ LL ≤ L ≤ H ≤ HH ≤ HH2`, пустой `Tag`, `Range_MIN ≥ Range_MAX`) выводятся пользователю с указанием `Tag` и поля.
7. Приложение запускается (WPF), главное окно работает, события импорта видны в журнале (белый/жёлтый/красный).
8. Таблица, созданная «с нуля» (F1.3), содержит все 130 колонок и индекс `UX_IO_LIST_Tag`; проверен импорт в таблицу с произвольным именем (не только `IO_LIST`); в базе без служебных таблиц `IO_LIST_Audit`/`MappingTemplates` создаются автоматически при записи.
9. Импорт без привязки `Tag` блокируется с ошибкой в журнале; неверно выбранная вкладка/строка заголовка — понятное сообщение с номером строки.
10. История: после импорта и редактирования `IO_LIST_Audit` содержит INSERT/UPDATE/DELETE со значениями «старое → новое»; выгрузка в `.xlsx` открывается в Excel.
11. **Правило идентичности (F2.8):** повторный импорт без изменений → счётчик «без изменений», записи в `IO_LIST_Audit` не прибавляются; существующий `Tag` с другими `System`/`Plant` → строка не изменена, в истории `CriticalError`, в отчёте код `E009`; импорт с выключенной галочкой «Импорт с аудитом» не создаёт записей истории (события журнала сохраняются).
11. Нечисловая шкала/уставка (напр. `<50`, `20±1`) сохраняется без потерь (TEXT) и даёт предупреждение валидации; числовые значения конвертируются и проходят проверку иерархии F5.2.
12. **Замена документа (F2.11/F2.16):** Apply в режиме «Добавить» спрашивает «Импортируется новый документ?»; при «Нет» предлагается список документов — **пары «файл + вкладка»** (`SELECT DISTINCT REV_FileName, REV_Sheet`, отображение «файл :: вкладка»); отсутствующие в новом файле теги **выбранной пары** помечены в `REV_Description` (остались в БД), в истории — `MarkedDelete` красным, в отчёте — предупреждения `W004` и счётчик «помечено к удалению»; строки других документов **и других вкладок того же файла** не затронуты; выжившие теги получают новую пару `REV_FileName`+`REV_Sheet` (+аудит Update, при смене вкладки — и по `REV_Sheet`); «Отмена»/отмена диалога — импорт не выполняется.
13. **Пустая шапка (F2.13):** при `HeaderRow = 2` и пустой ячейке заголовка имя колонки читается из строки 1 той же колонки; при `HeaderRow = 1` fallback не применяется.
14. **Дубликаты заголовков (F2.14):** лист с дважды встречающимся `MIN` даёт две строки маппинга с отображением «MIN (столбец …)» и подсказкой о дубликате; привязка `MIN`→`Range_MIN` и второй `MIN`→`Range_MIN2` импортирует значения из **разных** колонок Excel (резолв по позиции); старый шаблон без индекса загружается и резолвится по имени.
15. **Очистка Tag (F2.15):** `Tag` со вложенными пробелами/NBSP записывается без пробелов; в отчёте `W006`, в истории запись `TagCleaned` красным с контекстом «файл + вкладка + система»; в карточке сохранение также чистит `Tag`.
16. **Документ = файл + вкладка (F2.16/F7.7):** после импорта вкладки файла в `REV_Sheet` записано имя вкладки; импорт двух вкладок одного файла даёт два документа; `GetDocuments` возвращает обе пары; существующая база без `REV_Sheet` мигрирует автоматически (`ALTER TABLE ADD`), старые записи — NULL и матчатся с документом «без вкладки»; окно истории содержит колонку и фильтр «Вкладка», выгрузка Excel — колонку «Вкладка (REV_Sheet)».
17. **Формирование отчёта (F7.8):** кнопка «Формирование отчёта...» в окне истории открывает окно отчёта: по каждому документу «файл :: вкладка» — по каждой ячейке количество изменений по типам и «Всего» (напр. `Service: 56`), строки «ИТОГО» по документу и «ВСЕГО» равны сумме строк; отчёт учитывает текущие фильтры окна истории и считает **всю** таблицу аудита (сверка: при >500 записей истории итог отчёта не совпадает с `Records.Count`, но равен `COUNT(*)` по фильтру); внизу — «Документов: N · Всего изменений: M»; «Экспорт в Excel...» формирует `.xlsx`, где числа и итоги совпадают с экраном.
18. **Дубликаты тегов (F2.17а):** импорт файла, где тег встречается 2 раза, даёт: в `IO_LIST` — 1 запись (insert + upsert), в `IO_LIST_DublicateTag` — 2 копии (таблица создана автоматически, структура = `IO_LIST`, уникального индекса `Tag` нет); в отчёте — `W007` и счётчик «копий»; при 10+ повторах одного тега — `E005`, счётчик «массовых маркеров», ни одной записи в обе таблицы; повторный импорт не растит число копий в `IO_LIST` (уникальность сохраняется), копии добавляются по числу строк импорта.
19. **Замена нескольких документов (F2.17б):** диалог замены содержит список с множественным выбором (Ctrl/Shift + «Выбрать все»/«Снять всё», счётчик выбранных); при выборе двух документов (например, `f1.xlsx :: Лист1` и `f2.xlsx :: Лист2`) и импорте: теги обоих, отсутствующие в новом файле, помечены `MarkedDelete` (`W004`), теги третьего документа не тронуты; выжившие теги обоих перенесены на новый документ, в аудите `Update REV_FileName` OldValue = **прежний** документ каждой записи; запись, уже принадлежащая новому документу, не переносится (повторный прогон идемпотентен: 0 изменений).
20. **M_-поля (F9.0):** созданная таблица содержит 130 колонок (+ID), блок `M_*` расположен перед `CBL_Id`; существующая таблица из старой версии мигрирует автоматически при выборе (`EnsureColumns`); карточка точки показывает и редактирует M_-поля; `FieldRegistry`/`FieldDescriptions` содержат все 29 колонок.
21. **Импорт карты Modbus (F9.2):** окно «Импорт → Карта Modbus...» принимает несколько файлов; после «Импортировать и связать» `MODBUS_MAP` содержит все строки `Register Table` обоих файлов (EBSM102 ~799, EBSM103 ~801); повторный импорт того же файла не растит число строк (замена по `MapFile`); в `MODBUS_MAP` заполняется `LinkTag` для сопоставленных строк; окно показывает итоги по каждому файлу и связыванию, включая «карта: привязано X, без привязки Y» и до 10 строк «карта без привязки: <PlcTag>»; `MODBUS_MAP` не выбирается в списке таблиц главного окна и не является целью импорта Excel (просмотр в Access).
22. **Связывание (F9.3):** MCC-тег `…-MHS-… command:stop/start/permissive/ban` → строка Function 06 (общий Control word, `M_FuncCode=06`, адрес заполнен, `LinkTag` перечисляет все делящие его команды через запятую); `…-MXA-… fault/running/ready` → `_FAULT.MCU`/`_STA.MCU`/`_REDAY.MCU` Function 02 (бит); `…-MII-… current` → `_I_A` Function 03; тег со ссылкой в скобках «(1110-KM-101A-1)» связывается с базовым объектом карты (приоритет скобок); связывание заполняет `LinkTag`/`LinkState`/`DcsTag` строк карты (M_-поля при импорте не записываются — их пишет кнопка F9.4); итог связывания — «Проверено/Связано/Строк карты/Не связано/Карта (+ ошибки)»; несопоставимые перечислены в журнале.
23. **Задвоение между документами (F9.1):** импорт файла B поверх тега, существующего из файла A (не в режиме замены), создаёт в `IO_LIST_Audit` запись `Duplicate` (поле `Tag`, OldValue = «A :: вкладка», NewValue = «B :: вкладка»); запись отображается жёлтым в окне истории и выгрузке Excel, учитывается в отчёте F7.8 (колонка `Duplicate`) и в счётчике отчёта импорта (`W008`); повторный импорт того же файла дублей не создаёт; замена документов (F2.11) записей `Duplicate` не создаёт.
24. **DI-COM контуров и LinkState (F9.3):** DI-сигналы насосов с картой, использующей свои суффиксы (например `1120-PM-203A_Q3_F.PLC` «Motor 3 Fault», `…_Q3_READY.PLC` «Q3_Ready», `…_Q3_BYPS.PLC` «Operation/Running», `…_M3_PERMIT.PLC` «Permitted State»), связываются по ключевым словам роли в описании строки карты: `1120-MXA-00203A fault` → `_Q3_F.PLC`, `…00203B running` → `_Q3_BYPS.PLC`, `…00203C ready` → `_Q3_READY.PLC` (FuncCode 02); позиция автомата `_QF3_STA.PLC` («Switch Closing») и `_QF3_ATUO.PLC` («Remote/Local») статусами не считается; после связывания каждая строка `MODBUS_MAP` получает `LinkState` «привязано»/«не привязано» (сброс перед прогоном, разметка после; повторный прогон идемпотентен — счётчики и `LinkTag` не меняются); строка карты, у которой нет ни одной IO-записи (например `_TX.MCU` при отсутствии DI «communication»), корректно помечается «не привязано».
25. **Обновить адресацию Modbus (F9.4):** после импорта карты ни одна запись `IO_LIST` не содержит заполненных `M_*`-полей (связь хранится в `LinkTag`/`LinkState`/`DcsTag` строк `MODBUS_MAP`); колонка `DcsTag` заполняется эвристикой накопительно через запятую (`Tag` связанных точек, ручной ввод не затирается, дубли не добавляются) и переживает повторные прогоны связывания; кнопка «Импорт → Обновить адресацию Modbus» (тулбар «📡 Modbus адресация») по парам `DcsTag ↔ Tag` заполняет `M_*`-поля в одной сессии и пишет аудит `Update` по каждому изменённому полю (равноправно F7); итог — MessageBox со счётчиками «связей DcsTag / обновлено записей / тегов не найдено / ошибок» и списком ошибок (≤10); повторное нажатие идемпотентно (0 изменений); точка с `IO Type` без признаков Modbus (`M…`/`COM`), найденная по `DcsTag`, даёт ошибку «в карте адресации modbus указан DCSTAG не Modbus сигнала», `M_*` не заполняются; связывание (импорт) такой паре тоже отказывает с ошибкой и не пишет `DcsTag`/`LinkTag`. Ограничение распространяется на привязки F13: `M_BusBlock`/`M_BusDataOut` заполняются только для Modbus-сигналов (точка с `IO Type` «DI» получает ошибку в итоге кнопки «Записать привязки в IO_LIST»).
26. **Drag&drop окна импорта карты (F9.5):** файлы `*.xlsx`, перетащенные в `ModbusImportWindow`, добавляются в список «Файлы карты адресации» (все файлы, без дублей); не-Excel файлы в drop не принимаются (`DragDropEffects.None`); результат идентичен кнопке «Добавить файлы...».
27. **Гибкие классы (F9.6):** строка карты `9961-M-401_FAULT.MCU` (ObjectTag `9961-M-401`, FuncCode 02) связывается с точкой, чей кандидат — `9961-PM-401` (таблица PM↔M), `M_*` заполняются кнопкой F9.4; карта `9962-AG-1202A` связывается с кандидатом `9962-AGM-1202A` (AGM↔AG); точное написание класса приоритетнее эквивалентного; титул и числовой номер совпадают строго (перебор букв касается только класса); пустой класс не генерируется (минимум 1 буква).
28. **Ведущие нули (F9.7):** кандидат `9963-EM-3A` связывается со строкой карты `9963-EM-0003A_REDAY.MCU` и получает её адресацию (`M_PlcTag = 9963-EM-0003A_REDAY.MCU`); канонизация одинаково обрабатывает обе стороны (`003A` ↔ `3A`, в т.ч. в PlcTag с суффиксом: `00003A_TX.PLC` ↔ `3A_TX.PLC`) и не меняет титул/класс/хвост.
29. **Сообщения связывания в аудите (F9.8):** после связывания/обновления адресации в `IO_LIST_Audit` есть записи `ModbusWarning`/`ModbusError` с полем `Modbus`, `System` = «Modbus» и текстом сообщения в `NewValue` («связь отклонена … не Modbus-сигнал», «в карте адресации modbus указан DCSTAG не Modbus сигнала», «тег из DcsTag не найден в IO_LIST»); записи видны в окне истории (предупреждения — жёлтым, ошибки — красным), попадают в выгрузку Excel и учитываются в отчёте F7.8 (колонки `ModbusWarning`/`ModbusError`); `GetSummary`/`ReportBuilder` знают новые действия; запись выполняется после закрытия транзакции/сессии и не прерывает связывание при сбое аудита.
30. **Обновить связи Modbus без импорта (F9.9):** пункт меню «Импорт → Обновить связи Modbus (DcsTag)» и кнопка тулбара «🔗 Modbus связи» пересчитывают связывание текущей таблицы с уже сохранённой картой `MODBUS_MAP` (без файлов): строки карты получают обновлённые `LinkTag`/`DcsTag`/`LinkState` после ручных правок/добавления сигналов в Access; итог — MessageBox с примерами «Не связано»/«Карта без привязки» и ошибками; при пустой `MODBUS_MAP` — подсказка импортировать карту; `M_*`-поля не записываются (F9.4).
31. **Отключение аудита (F9.9):** чекбокс «Вести аудит (IO_LIST_Audit)» в окне импорта карты переключает глобальный `AuditService.Enabled`; при выключении: `Record()` и пакеты (`BeginBatch`/`EndBatch`) не пишут в `IO_LIST_Audit` (история не растёт), сообщения связывания F9.8 в историю не попадают, но в журнале событий остаются сообщения связывания и минимализированные записи об изменениях — единичные «Аудит выключен: изменён тег «X»», пакетные — одна сводная строка со списком уникальных затронутых Tag (≤20 + «…»); при повторном включении аудит пишется как прежде.
32. **Роли VFD/скорость/run (F9.10):** точка `2711-MXA-27116B` (Service «SM Transfer Pump 2711-P-1302A **run signal**», `DI-COM`) связывается со строкой карты `2711-PM-1302A_STA.MCU`; `MSC-31201` (`AO-COM`, «speed control») → строка «VFD Frequency Setting» (Function 06), `MSI-31201` (`AI-COM`, «speed signal») → `_OP_F` «Operating Frequency» (Function 03) и **не занимает** «Output Current»; четыре команды `MHS-…A/B/C/F` (stop/start/permissive/ban) одного VFD привязываются к строке «Control word … Value:1=Stop,…» (Function 06), а не к «Frequency Setting» — в `LinkTag` Control word все четыре тега через запятую, у «Frequency Setting» — только `MSC`; Service без ключевых слов распознаётся по суффиксу тега (`MXA…A/B/C` → fault/run/ready); карта `2622-BLM-101A` связывается с кандидатом `2622-BL-101A` (эквивалент `BLM↔BL`).
33. **Ручные правила связывания (F9.11):** в существующей базе при открытии/записи служебных таблиц создаётся `MODBUS_LINK_RULES` (идемпотентно; повторная миграция существующей базы не трогает уже сохранённые правила); окно «Импорт → Правила связывания Modbus...» позволяет добавить/изменить/выключить/удалить правило и сохранить его (валидация: название, допустимые `IOField`/`MapField`, корректность шаблонов; невалидное правило не сохраняется), кнопка «Проверить» показывает результат без записи. Правило `TagPattern=1115-MXA-00101A` (или wildcard `*MXA*A`/regex `MXA.*A`) → `MapField=PlcTag`, `ValuePattern=*_TX.MCU*` при следующем связывании **перехватывает** точку `1115-MXA-00101A` у встроенной роли `FAULT.MCU` (строка `_TX.MCU` получает `LinkTag`, строка `_FAULT.MCU` остаётся без привязки; в журнале — перечень сработавших правил, в итоге — «правилом F9.11: 1»); при двух правилах на одну точку побеждает правило с меньшим `Priority`; правило с `FuncCode=06`, не совпавшим с `FuncCode` строки карты, не применяется — точка связывается встроенной ролью; выключенное правило (`Enabled=0`) не применяется, но остаётся в БД; после удаления всех правил поведение возвращается к встроенным ролям. Шаблон с метасимволами regex (`. + [ ]` и т.п.) интерпретируется как регулярное выражение, начинающийся с `*`/`?` — как wildcard; невалидный regex не прерывает связывание (правило пропускается с предупреждением).
34. **Генерация перечня Тех.объекты (F12):** в существующей базе при открытии/записи служебных таблиц создаются `SCADA_TYPE_MAP` (сид — 9 соответствий типа из раздела 2.5.4, только при создании) и `SCADA_TEHOBJ_SETTINGS`; меню «SCADA → Генерация перечня Modbus (Тех.объекты)...» открывает окно, «Построить превью» включает только точки с заполненным `M_PlcTag` (без адресации — пропуск со счётчиком), Марка формируется из выбранного поля с заменой «-» на «_» и ведущим «_» (`1115-MHS-00101A` → `_1115_MHS_00101A`), поле-источник/константа любого поля задаётся тремя формами — колонка IO List, структура с подстановками `{ИмяКолонки}` (напр. Наименование `{Service} ({Loop})` → «V-6704, блок. отсечки (3103-XZV-67401)», Марка `PRE-{Tag}` → `_PRE_3103_XZY_67401`, константа Группа событий `{Tag}` → `3103-XZY-67401`) или произвольный текст; неизвестная колонка в структуре → предупреждение с именем поля, значение остаётся литералом; обрезка ≤50 — только у Доп.параметра; «Сформировать Excel...» сохраняет файл с шапкой в 4 строки (группы «Cлужебные»/«ОБЩЕЕ СВ-ВО», русские заголовки, имена `MARKA`/`OBJTYPE`/…) и данными с 5-й строки, 20 колонок: Раздел `TEHOBJ`, Тип объекта — через `SCADA_TYPE_MAP` (немапп. тип остаётся исходным + предупреждение), Наименование `Service`, Описание `Loop`, KKS `Tag`, КОНТРОЛЛЕР `Controller`, Период архив/Адрес = 0, Шаблон `простой`, Доп.параметр — по шаблону с `{M_*}` и ≤50 символов; настройки сохраняются в `SCADA_TEHOBJ_SETTINGS` и восстанавливаются при следующем открытии; таблица маппинга типов редактируется в окне и сохраняется в `SCADA_TYPE_MAP` (полная замена); удаление таблиц и повторное `EnsureServiceTables` воссоздаёт их с сидом (повторная миграция не трогает сохранённые пользователем строки).
35. **Генерация блоков Modbus (XML) (F13, шаблонная):** в существующей базе при открытии/записи служебных таблиц создаются `SCADA_MB_SETTINGS`, `SCADA_MB_SLAVE_RULES` и **`SCADA_MB_TEMPLATE`** (`Name` TEXT(50)/`Body` MEMO) (идемпотентно); в `IO_LIST` добавляются колонки **`M_BusBlock`/`M_BusDataOut`** (FieldRegistry, DDL, миграция `EnsureColumns` → 130 колонок); меню «SCADA → Генерация блоков Modbus (XML)...» открывает окно с группой «XML-шаблон»: режим «Файл» (путь настройки, иначе авто-поиск `MB_TCP_MASTER_пример_new.xml`: каталог exe → `Work\` → встроенная копия) или «Код» (многострочный ввод → `SCADA_MB_TEMPLATE` при «Сохранить настройки»); «Проверить шаблон» валидирует (корень `BufScadaPOUS`, блоки, мастер по имени объекта `MB_TCP_MASTER`/`MB_RTU_MASTER` — см. F15) и показывает «мастер MB_TCP_MASTER_4_1; блоков: 10; связей: 9»; мусор/шаблон без мастера — текст ошибки. «Построить превью» включает только точки с заполненным `M_PlcTag` (без адресации — пропуск со счётчиком; `FuncCode` 06/15/16 — «запись», пропуск; IP из `M_SlaveIdMain` «192.168.4.10(Default)↵255.255.255.0↵port 502» → адрес + порт 502) и формирует пакеты «IP × порт × код функции»: политика «Непрерывные диапазоны» (по умолчанию) — точки 0,1,2 + 10 на одном устройстве дают **2 пакета** (Count 3 и 1); «Покрытие min..max» — те же точки одним пакетом Count=11 (при лимите 8 прореха 2..10 делит пакет); «Фиксированные» с MaxCount=5 — пакеты 0..4 и 10, пустые пачки пропускаются; две точки 32-Bit Floating по адресам 0 и 2 → один пакет Count=4; лимит Count = min(MaxCount, 123 регистров/246 бит). Каждый пакет получает имя блока от шаблонного мастера (`MB_TCP_MASTER_4_1 → _4_2 → _4_3`, сквозная нумерация) и привязки `DataOut[i]` (индекс = адрес − Address пакета; float-точка по адресу 2 → `MB_TCP_MASTER_4_3.DataOut[2]`); сетка привязок в окне показывает «Тег | Адрес | Смещение | Блок | Привязка». «Сформировать XML...» сохраняет два файла (основной + «{имя}_bindings.xml» рядом): основной — well-formed `BufScadaPOUS`, `Common`/`OnePOU`/`ISAOBJSINFO` из шаблона (`TENIXRT-CPU850`, `MB_Master_4`, `TenixRtLib`), юнит шаблона клонируется на пакет: подстановки по связям — `SlaveId=7` (правило «IMCS EBSM102 → 7», станции без правила — `DefaultSlaveId`), `Mode=2`, `Address`/`Count` пакета, таймаут `100` мс из `M_Timeout` вместо шаблонного `200`; `IV` мастеров содержит IP/порт (`…,192,168,4,10,502`); имена инстансов сдвигаются (`PULSE_1→PULSE_2/PULSE_3`, `TON_8→TON_9/TON_10`), `T11ID` всех блоков уникальны, `cardId` первого мастера — шаблонный `597529`, клоны — новые (`624603`, `624633`, …) с `rec` в `ISACARDSINFO` (Info = новое имя), кластер пакета 2 сдвинут на ColumnStep (X=1472); файл привязок — корень `<BufScada>`, `PageMode="4"`/`PageID="19054"` (ID OnePOU), по блоку 31 на каждую пару (блок, индекс): `Info="MB_TCP_MASTER_4_1.DataOut[0]"`, `T11Text=".DataOut[0]"`, `cardId`/`IV` мастера пакета, `ISACARDSINFO`/`ISAOBJSINFO` с rec мастеров. Кнопка «Записать привязки в IO_LIST»: у точек пакетов заполняются `M_BusBlock`/`M_BusDataOut` (обновлено 3), точка с `IO Type` «DI» даёт ошибку («не Modbus-сигнала»), повторное нажатие идемпотентно (0 изменений), точка, выпавшая из плана, **очищается** (`Cleared=1`); аудит — `Update` по полю `M_BusBlock` (IO_LIST_Audit).  43. **F21 — станции из IO_LIST: параметры станции в `SCADA_MB_SLAVE_RULES` (2026-10):** таблица правил «станция → SlaveId» дополнена колонками IO_LIST: `IpMain`/`IpReserve` (IP основной/резерв), `Protocol` (TCP/RTU), `Speed`, UART (`Parity`/`StopBit`/`DataBit`), `Reverse`, `Timeout`, `MaxLength`; старые базы дополняются идемпотентно. `FillSlaveRulesCommand` («Заполнить из IO_LIST») строит правила из `M_SlaveStation`/`M_SlaveIdMain` и IP станции, SlaveId существующих правил не затираются; протокол станции определяет выбор мастер-шаблона (F22), RTU-пакеты планируются с `IsRtu`.
 44. **F22 — именованные мастер-шаблоны и генерация по протоколу станции (2026-10):** мастер-шаблоны блоков — таблица `SCADA_MASTER_TEMPLATES` (Name/Protocol/Body/FilePath; Protocol со «RTU» → RTU, иначе TCP): CRUD-список в окне (залить из файла, сохранить, удалить) + настройки `MasterTemplateName`/`MasterRtuTemplateName`; шаблоны привязок DataIn — `SCADA_DATAIN_TEMPLATES` (хранилище без генерации). `ScadaTemplateXmlService.WriteProtocolSplit` генерирует по протоколу станции: TCP-пакеты — из TCP-шаблона, RTU — из RTU-шаблона, склейка в один `BufScadaPOUS` с уникальными T11/Info (`MergeSplitResults`); без RTU-шаблона RTU-пакеты пропускаются с предупреждением в `Warnings` (→ журнал/статус экспорта).
 45. **F23 — переменные шаблона: маппинг «вход → колонка/литерал» (`SCADA_TEMPLATE_VARS`, 2026-10):** таблица `SCADA_TEMPLATE_VARS` (Scope/TemplateName/Var/IoColumn/Literal) хранит маппинг переменных генерации; скоуп `master` — входы мастера (dataout/datain — в плане после приёмки master). UI «Переменные мастер-шаблона»: входы парсятся из связей текущего шаблона (`ParseInputVariables`: SlaveId/TimeOut/Mode/Address/Count/…), для каждой — колонка IO_LIST (ComboBox из FieldRegistry) или литерал; колонка «Источник» показывает подстановку без маппинга («из плана» — SlaveId/Mode/Address/Count/TimeOut из расчёта пакета, «из шаблона» — значение шаблона). «Сохранить маппинг» пишет строки скоупа master (полная замена), при экспорте `ApplyTemplateVarsToPackets` заполняет `MbPacketPlan.VarValues` значением колонки первой точки пакета (`ColumnValues`) либо литералом; генератор имеет приоритет `VarValues` над источником из плана (числовой Address форматируется как вход блока), пустая колонка/неизвестная переменная — источник из плана с предупреждением в журнале; константа-источник (GROBJTYPE=34) получает `Info`/`T11Text`, тег — IV.
 46. **F24 — токены `{ИмяКолонки}` в паттернах имён блоков/POU (2026-10):** `MbPacketPlan` несёт `ColumnValues` — колонки IO_LIST первой точки пакета (`ColumnValuesOf(IoPoint)`, заполняется в `BuildPlan`); `ApplyBlockNamePattern` (имя блока) и `BuildPouName` (имя POU) после служебных токенов `{Seq}/{Slave}/{Station}/{Ip}/{Func}/{Port}` резолвят `{ИмяКолонки}` по значениям пакета (пробелы/точки → `_`), неизвестный токен остаётся литералом как есть; примеры паттернов: `MB_{Tag}_{Seq}`, `{M_SlaveStation}_POU`. Приёмка: **450 проверок смоука пройдена** (F23 — 11, F24 — 6; регрессия F13–F22 зелёная).

## 8. Ограничения и допущения

1. **Допущение:** состав колонок любого IO List задаётся маппингом в окне сопоставления (авто-определение + ручное уточнение); фиксированная структура листов не требуется.
2. **Ограничение:** только Windows + ACE OLE DB (OleDb не кроссплатформенный); для старых `.mdb` — Jet 4.0.
3. **Допущение:** код `AIR-EP(3 WIRES)` нормализуется до `AI-EP`; иные составные коды обобщаются правилом «базовый код + примечание» (примечание — в `column1…column10`).
4. **Ограничение:** ревизии файлов (`Rev`, «frozen version», папки `old/`) — не версионируются в БД автоматически; версионность — через `REV_FileName` + `REV_DateEntered`. Полное версионирование (таблица `document` + снапшоты) — отдельная итерация.
5. Справочники берутся из раздела §9 `IOclass.md` (строки); `GDS_Schema.sql` как эталон не используется (см. «История / архив v0»).
6. Права на запись в файл БД предполагаются обычными пользовательскими (не требуются права администратора).
7. **Допущение:** `Logic` хранится одной строкой (полный `Logic No`); разбиение на отдельные логики и роли (main/setpoint) — вне объёма v0.
8. **Допущение:** шкалы и уставки хранятся как TEXT (нечисловые данные не теряются); числовая интерпретация — только при валидации (F5.2/F5.3) по правилам конвертации F2.3.
9. **Допущение:** история изменений ведётся в служебной таблице `IO_LIST_Audit` той же базы; выгрузка истории — в Excel (F7).
